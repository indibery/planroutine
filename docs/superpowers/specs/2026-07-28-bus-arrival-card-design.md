# 버스 도착 카드 — 설계

## 개요

오늘 탭 최상단에 **출퇴근 버스 실시간 도착시간 카드**를 얹는다. 데이터는 TAGO(국가대중교통정보센터)
공공데이터이고, **앱이 TAGO를 직접 호출한다**(서버 없음).

정류장은 **출발지·도착지 2개 슬롯**만 갖고, 설정 탭에서 언제든 교체한다. 카드는 **기본 OFF**이고
켜지 않은 사용자의 화면은 1픽셀도 바뀌지 않는다.

프록시 서버는 **보류**다 — 지금 규모에서 값을 못 하고, 승격 조건을 §5에 명시했다.

기획 원본: 옵시디언 `60 프로젝트/플랜루틴(PlanRoutine)/공직플랜 버스 도착 기능 기획.md`

## 배경 — 왜 옵트인인가

이 앱의 목적축은 "매년 반복되는 교사 업무 사이클을 작년 데이터 기반으로 세팅"이다. 오늘 탭은
그 축의 끝단으로, 업무를 체크해 도장을 찍고 결산 링을 채우는 화면이다. **버스 도착은 그 축 밖의
정보**라, 상시 노출하면 화면의 주제가 둘이 된다.

그리고 이 앱은 화면 높이를 예산처럼 다룬다. 진행도 텍스트(`149 / 149 · 100% 완료`)를 지운 이유,
필터 칩을 접은 이유, 중요 배지를 인라인 ★로 바꾼 이유가 전부 픽셀 지출이었다. 카드는 약 80px을
쓴다 — 이 앱에서 작지 않은 지출이다.

그래서 **`설정 > 버스 도착 > 표시` 스위치 기본 OFF**로 두고, 켠 사람만 지출한다. 도장 모양 설정·
`SlideHintBar` 영구 닫기와 같은 계열의 결정이다.

## 기획 원본에서 뒤집은 것 3가지

원본 기획은 Laravel + MySQL + Redis + Sanctum 스택을 전제했다. 확인 결과 **공직플랜에는 백엔드가
없다**(`pubspec.yaml`은 sqflite 로컬 전용, `i_code/`에 Laravel 프로젝트 없음, 볼트의 Laravel 코드는
종료된 민원시스템). "기존 방식 재사용"할 대상이 존재하지 않는다.

### 1. 서버 DB + 로그인 → 서버 없음

원본은 `출발/도착 정류장 저장 → 서버 DB (기기 바꿔도 유지)`를 골랐다. 이 한 줄이 회원가입·로그인·
Sanctum 토큰·계정 삭제 기능(App Store 심사 필수)을 전부 끌고 온다. **지금 공직플랜은 로그인이
없는 앱**이다.

게다가 일관성이 안 맞는다 — 기기를 바꾸면 일정·이벤트가 **이미 전부 사라진다**(sqflite 로컬 전용).
정류장 2개만 클라우드에 두는 것은 앱의 나머지와 어긋난다.

정류장을 `shared_preferences`에 둔다. **대가**: 기기 교체 시 정류장 2개를 다시 등록해야 한다(수용).

원본이 서버를 둔 나머지 이유(인증키 은닉·호출량 통제)는 프록시만으로 충족되고 로그인이 필요 없지만,
그 프록시조차 지금 규모에서는 값을 못 한다 — §2에서 다룬다.

### 2. 두 정류장 항상 표시 → 지금 방향만 + 토글

원본 스케치는 출근·퇴근 정류장을 항상 같이 보여준다. 그러나 **아침 7시 32분에 학교앞 정류장의
실시간 도착시간은 쓸모가 없다.** 실시간 정보의 유효기간은 몇 분뿐이고 퇴근은 8시간 뒤다.

| | 둘 다 표시 | 지금 방향만 |
|---|---|---|
| 오늘 탭 화면 지출 | ~140px | **~80px** |
| TAGO 점유 정류장 | 2개 | **1개** |
| 한도상 동시 사용자 | 약 250명 | **약 500명** |

한도 계산 근거: 서버 캐시가 없으니 **폴링 주기가 곧 호출 주기**다. 정류장 1개 × (5분 관측 / 30초
폴링) = 10 호출, 출퇴근 왕복 2회면 20 호출/일/명. 개발계정 10,000/일 ÷ 20 = 500명. 정류장을
2개 점유하면 절반이 된다. (운영계정 승격 시 10배.)

쓸모없는 정보를 지우면 화면 예산과 호출 예산이 **동시에** 절반이 된다. 지난 항목을 롤링 7일로
자르고 기본 접은 것과 같은 규율이다.

그 결과 원본 6번의 ⭐ 항목 "시간대별 출근/퇴근 자동 전환"의 의미가 바뀐다 — 순서를 뒤바꾸는 게
아니라 **어느 정류장을 폴링할지 고르는 스위치**가 된다. 로직은 더 단순하고 효과는 더 크다.

### 3. 신호등 색 → 신호등 **모양** 3색

원본은 `3분↓ 빨강 / 3~7분 노랑 / 그 이상 초록`이다. 색만 쓰면 이 팔레트와 충돌한다 —
노랑은 골드와 물리적으로 구별되지 않고, 현재 색 규칙은 이미 포화 상태다
(`골드=오늘·중요` / `붉은색=공휴일·일요일` / `파랑=토요일·이벤트`).

해법은 색을 줄이는 것이 아니라 **관용 형태를 주는 것**이다. 신호등 모양 안에 놓인 빨강·노랑·초록은
"공휴일 빨강"이나 "중요 골드"로 읽히지 않는다. 형태가 색의 문법을 지정한다.

부수 효과가 본질적이다 — **어느 칸이 켜졌는가**라는 비색상 단서가 생긴다. CLAUDE.md가 ★를
남긴 논리("남은 신호 셋이 전부 색이라 형태가 마지막 비색상 단서다")와 같고, 색맹 사용자에게도
작동한다.

## 1. 카드 UI

가로 3구. 행 높이를 쓰지 않고, 한국 차량 신호등 순서(좌→우 빨강·노랑·초록)와 일치하며,
왼쪽=임박 / 오른쪽=여유가 위치로 읽힌다.

```
┌───────────────────────────────────┐
│ 🏠→🏫 출근 · 시청앞      07:32 기준 │
│   (●○○)  720번     2분             │
│   (○●○)  150번     5분             │
│   (○○●)  15번     11분             │
│                    [ 퇴근 보기 ⌄ ] │
└───────────────────────────────────┘
```

- **꺼진 칸은 지우지 않고 어둡게 남긴다.** 안 남기면 점 하나가 색만 바뀌는 것이 되어 위치 단서가
  사라진다.
- 세로 3구는 행 높이를 3배 써서 80px 예산에 맞지 않는다.
- `07:32 기준`은 마지막 조회 시각이다 (§2 경과 보정 참조).
- 방향 토글은 **수동 우선**이다. 누르면 그 화면 수명 동안 유지되고 저장하지 않는다 — 다시 열면
  다시 시각 기준으로 돌아간다. 필터 접힘 상태와 같은 수명 규칙이다.

### 자동 전환 기준

**정오 12:00 고정.** 이전은 출근(집→학교), 이후는 퇴근(학교→집). 교사 일과가 출근 7~8시 /
퇴근 16~17시로 뚜렷해 경계가 애매한 구간이 실질적으로 없다. 설정 항목을 늘리지 않고, 어긋나는
날(야간 자율·조기 퇴재)은 토글이 탈출구다.

### 색 토큰

`AppColors`에 4개를 **추가**한다(기존 값 변경 없음). 다크·라이트 두 `_Palette`에 모두 넣는다.

| 토큰 | 다크 | 라이트 | 용도 |
|---|---|---|---|
| `busSignalNear` | `#EF5F52` | `#CF3A2A` | 3분 미만 |
| `busSignalSoon` | `#F2B23C` | `#C98A0E` | 3~7분 |
| `busSignalFar` | `#5FC98A` | `#1E9E63` | 7분 초과 |
| `busSignalOff` | `#33F0EAD9` | `#D4DBE6` | 꺼진 칸 |

이름에 `bus`를 박는 이유가 있다. 이 색들은 **신호등 형태 안에서만** 유효하다 — 다른 곳에서
`busSignalSoon`을 강조색으로 갖다 쓰면 위에서 회피한 팔레트 붕괴가 그때 일어난다. 이름이 오용을
막는다.

라이트의 노랑은 흰 배경 대비가 없어 딥 앰버(`#C98A0E`)로 잡는다. 이 값은 라이트 `gold`(`#9A7415`)와
색상이 인접하다 — 신호등 형태가 문맥을 주므로 수용하되, **실기기에서 확인할 항목**으로 남긴다.

## 2. 아키텍처 — 앱이 TAGO를 직접 호출한다

```
[Flutter: features/bus/]
  shared_preferences  정류장 2슬롯 + 도시코드 + ON/OFF
  TAGO 키             --dart-define=TAGO_KEY (리포에 커밋하지 않음)
  메모리 캐시 30초      정류장별. 방향 토글 왕복 시 재호출 방지
  폴링 30초            오늘 탭이 살아있고 앱이 포그라운드일 때만
      │  https — ATS 예외 불필요
      ▼
[TAGO 1613000]  ArvlInfoInqireService / BusSttnInfoInqireService
```

### https는 실측으로 확인했다

기획 원본 8번의 curl 예시가 `http://`라 iOS ATS(App Transport Security) 예외와 심사 소명이
필요할 수 있었다. 이것이 프록시의 숨은 이득 중 하나였는데, **불필요함이 확인됐다**(2026-07-28).

```
subject: C=KR; O=National Information Society Agency; CN=*.data.go.kr
issuer:  GlobalSign RSA OV SSL CA 2018
SSL connection using TLSv1.3   ssl_verify_result=0
더미 키 요청 → HTTP 401        (TLS 정상, 키만 거부)
```

`Info.plist`에 ATS 예외를 넣지 않는다. 모든 요청은 `https://apis.data.go.kr`로 간다.

### 왜 지금은 서버를 두지 않는가

프록시의 논거는 셋이었고 둘이 무너졌다.

1. ~~한도~~ — 위 계산대로 앱 직접 호출로도 **약 500명**까지 버틴다. 지금 규모에서 한도는
   서버를 정당화하지 못한다.
2. ~~ATS 우회~~ — https 실측으로 비용이 0이 됐다.
3. **고칠 수 있는 속도** — 유일하게 남은 논거. 유효하지만 이것은 보험이고, 지금은 보험료가
   기능 자체보다 비싸다.

### 되살아나는 리스크와 완화 (수용)

| 리스크 | 앱 직접의 대가 | 완화 |
|---|---|---|
| 키 탈취 | 재발급 + 앱 수정 + **심사 1~3일**, 그동안 기능 정지 | 개발계정 키는 무료·즉시 재발급. 사용자가 적어 피해 규모도 작다 |
| 한도 관측 | 서버 대시보드가 없다 | data.go.kr 마이페이지의 일일 호출량을 릴리즈마다 눈으로 확인 (§5) |
| 폴링/TTL 조절 | 심사 뒤에 잠긴다 | 폴링 30초로 보수적으로 시작 — 조일 일은 없고 풀 일만 남게 |
| TAGO 응답 포맷 변경 | 구버전 사용자가 계속 깨진다 | 파서를 관용적으로 짠다 — 모르는 필드 무시, 결측 허용, 실패 시 빈 목록 |

### 키 관리

`--dart-define` 선례가 이미 있다 — `main.dart:13`의 `bool.fromEnvironment('SCREENSHOT_MODE')`.
같은 패턴으로 `String.fromEnvironment('TAGO_KEY')`를 쓴다.

- **리포에 커밋하지 않는다.** 로컬 보관은 리포 밖(`~/.planroutine/tago_key`).
- `Fastfile:272`의 `sh("flutter", "build", "ipa", ...)`에 `--dart-define=TAGO_KEY=#{key}`를
  추가하고, **키를 못 읽으면 레인을 실패시킨다.** 키 없이 빌드하면 기능이 조용히 죽은 앱이
  스토어에 올라간다 — 조용한 실패를 막는 가드다.
- **Decoding 키를 넣는다.** Dart `http`가 쿼리 파라미터를 인코딩하므로 Encoding 키를 넣으면
  이중 인코딩으로 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 난다(원본 8번 함정 1번).
- **난독화는 방어가 아니다.** 키는 IPA 안에 문자열로 남는다. `--dart-define`의 실질 가치는
  **git 히스토리에 남지 않는 것**이다 — 이 리포는 과거 실데이터를 히스토리에서 제거한 이력이 있다.

### 캐시와 경과 보정

서버가 없으니 Cloudflare KV의 60초 최소 TTL 제약이 사라졌다. 앱 메모리 캐시라 TTL이 자유롭다.

- 폴링 30초 = 호출 주기. 메모리 캐시 TTL도 30초로 맞춘다.
- 캐시의 역할은 둘이다 — **방향 토글로 왕복할 때**(30초 안에 출근↔퇴근을 오가면 두 번째부터
  캐시가 답한다), 그리고 **탭을 옮겼다 오늘 탭으로 돌아올 때**(빈 카드가 깜빡이지 않는다).
- 그래서 캐시는 `bus_api_client` 인스턴스가 들고, **client provider는 `autoDispose`가 아니다.**
  카드 provider만 autoDispose다. 둘 다 autoDispose로 두면 탭을 옮길 때마다 캐시가 사라져
  두 번째 역할을 못 한다. 대신 슬롯이 교체되면 캐시를 명시적으로 버린다(§6 push 함정 참조).
- 캐시 히트일 때 값이 최대 30초 묵으므로 **경과 보정**을 넣는다.

```dart
// bus_card_view.dart
final elapsed = now.difference(fetchedAt).inSeconds;
final displayMin = ((arrival.arrMin * 60 - elapsed) / 60).ceil();
```

"4분"으로 받은 값이 50초 묵었으면 화면에는 **3분**으로 나간다. 캐시가 30초 TTL이라 오차는
30초 이내지만, 보정은 폴링이 늦어졌을 때(백그라운드 복귀 직후 등)도 함께 지킨다.

### 프록시로 승격할 때 앱 변경이 작게 유지되도록 짠다

정규화·판정을 `data/tago_response_parser.dart`의 **순수 함수**로 분리한다. 프록시를 도입하면
이 파일이 서버로 그대로 옮겨가고, 앱에는 base URL 교체와 키 주입 제거만 남는다. 지금 이 분리를
해두지 않으면 승격 비용이 "다시 설계"가 된다.

## 3. 실패 계약 — 신뢰의 급소

원본 6번이 "명확한 빈 상태 문구 — 신뢰에 직결"이라고 짚은 것을 계약으로 못박는다.
**다섯 상태가 화면에서 서로 구분돼야 한다.**

| 상황 | 판정 근거 | 카드 표시 |
|---|---|---|
| 정상 | `resultCode == '00'` + items 있음 | 목록 + "07:32 기준" |
| 도착정보 없음 (막차 후 등) | `resultCode == '03'`(NODATA) 또는 items 빈 배열 | "오늘 운행이 끝났어요" |
| 네트워크/TAGO 장애 + 캐시 있음 | 예외 발생, 메모리 캐시 존재 | 캐시 목록 + "07:30 기준 (갱신 실패)" |
| 장애 + 캐시 없음 | 예외 발생, 캐시 없음 | "지금 정보를 못 받았어요 · 다시 시도" |
| **키 문제** | HTTP 401 또는 `SERVICE_KEY_*` | "버스 정보를 불러올 수 없어요" + 로그 |

앞의 넷은 프록시 설계에도 있었다. **다섯째가 앱 직접 호출에서 새로 생긴다** — 서버가 없으니
키 오류가 사용자 화면까지 도달한다. 사용자에게 키 이야기를 하지 않는다(할 수 있는 일이 없다).
개발자가 알아채는 경로는 로그와 §5의 호출량 점검이다.

`buses: []`와 장애를 같은 문구로 뭉개면 사용자가 "막차 끝남"과 "앱 고장"을 구별할 수 없다.
버스 앱에서 이 둘의 차이는 **정류장에서 기다릴지 택시를 부를지**를 가른다.

### 정규화 (`tago_response_parser.dart`, 순수 함수)

- `arrtime`(초) → `arrMin`: `ceil(sec / 60)`, 0이면 "곧 도착"
- `arrtime` 오름차순 정렬
- `vehicletp` → `lowFloor` bool
- 모르는 필드는 무시하고, 결측 필드는 null로 받는다 (포맷 변경 내성)
- 단건 응답이 객체로, 복수 응답이 배열로 오는 공공데이터 특유의 형태를 둘 다 받는다

## 4. 정류장 등록 — 방향이 조용히 틀리는 것을 막는다

**TAGO `nodeId`는 방향별로 별개다.** "시청앞" 한 곳이 아니라 상행 정류장 / 하행 정류장이 각각
다른 ID를 갖는다. 길 건너 마주보는 두 정류장이 같은 이름이다. 잘못 고르면 화면에는 버스가 정상적으로
뜨지만 **전부 반대 방향**이다 — 사용자는 앱이 고장 났다고 생각하지 않고 자기가 늦었다고 생각한다.

### 저장 직전 확인 시트

정류장을 탭하면 바로 저장하지 않고, 그 정류장에 실제로 오는 버스를 한 번 조회해 보여준다.

```
┌─────────────────────────────┐
│  이 정류장이 맞나요?           │
│  시청앞 (12-345)             │
│                             │
│  지금 이 정류장에 오는 버스     │
│   720번   4분 후             │
│   150번   11분 후            │
│   15번    운행 종료           │
│                             │
│    [ 아니에요 ]  [ 맞아요 ]   │
└─────────────────────────────┘
```

방향은 좌표나 이름으로 사람이 판별할 수 없지만 **자기가 타는 버스 번호는 안다.** 노선 번호를
보여주면 사용자가 스스로 맞는 쪽을 고른다. 도착정보 조회 경로를 그대로 재사용한다.

### 검색 방식 — 이름 검색만

`getSttnNoList`(이름 검색)는 `cityCode`가 필수라 "도시 선택 → 정류장명" 2단이 된다.
`getCrdntPrxmtSttnList`(좌표 근접)는 위·경도만 받아 도시 선택을 우회하지만, **GPS는 교체
시나리오에서 못 쓴다** — 3월에 학교를 옮기면 새 학교 정류장을 집에서 등록하고, 이사하면 새 집
정류장을 이사 전 집에서 등록한다. 대상 정류장 근처에 없는 것이 교체의 기본값이다.

이름 검색만 넣는다. 새 의존성 0, 새 권한 0, 위치 권한 소명 0. 도시는 마지막 선택을 기억해 매번
고르지 않는다.

## 5. 한도 관측과 프록시 승격 조건

서버가 없으니 호출량을 자동으로 볼 수 없다. **수동 점검 지점을 정해둔다.**

- **점검 위치**: data.go.kr 마이페이지 → 오픈API → 활용 현황 (일일 호출량)
- **점검 시점**: 버스 기능이 포함된 릴리즈마다 + 이후 월 1회
- 이 절차를 `docs/release_checklist.md`에 한 줄 추가한다 — 기억에 의존하면 점검하지 않는다.

### 승격 조건 (하나라도 만족하면 프록시를 도입한다)

1. 일일 호출량이 **6,000회**(개발계정 10,000의 60%)를 넘긴 날이 관측된다.
2. 운영계정(100,000/일)으로 승격한 뒤에도 여유가 20% 미만이다.
3. 키 오용·탈취 징후가 있다(내가 쓰지 않는 시간대의 호출량, 급증).
4. TAGO 응답 포맷이 바뀌어 구버전 사용자가 깨지는 일이 실제로 발생한다.

승격 시 작업은 §2 마지막 항목대로 **`tago_response_parser.dart`를 서버로 이동 + base URL 교체**다.
그때 설계는 이 문서의 이전 리비전(git 히스토리)에 프록시 안으로 남아 있다 — Cloudflare Workers
+ KV 60초 + 무상태 + rate limit 안이다.

`buildTodayView`·`computeNotifications`·`buildFilterSummary`와 같은 자리다. DB도 플랫폼도 모르니
색상 경계·경과 보정·5상태를 전부 유닛 테스트로 고정한다.

### 설정 탭

`SettingsSection(title: '버스 도착')`:
- `표시` 스위치 (기본 OFF)
- ON일 때만 슬롯 2줄: `출발지 · 시청앞`, `도착지 · 학교앞` → 탭하면 `/bus/stops` push

### 오늘 탭 배선 — `buildTodayView`는 건드리지 않는다

카드는 `today_body.dart` 최상단에 조건부로 들어가지만 `TodayView`에는 섞지 않는다.
`buildTodayView`는 업무 완료·진행도 계산 함수이고 버스는 그 도메인이 아니다. 섞으면 순수 함수
하나가 두 주제를 갖고 기존 테스트가 흔들린다. 카드는 별 provider를 watch하는 형제 위젯이다.
**기존 480개 테스트는 무손상이다.**

### CLAUDE.md의 push 함정이 여기 정확히 걸린다

> ⚠️ `push`는 예외다. `push`로 덮인 화면은 offstage로 마운트가 유지돼 autoDispose가 걸리지 않는다.
> **오늘 탭에 push 라우트를 붙이면** 그 화면이 리비전을 올리지 않는 한 pop 후 목록이 stale이 된다.

카드의 빈 상태에서 `/bus/stops`로 push하면 이 조건이 성립한다. 정류장을 바꿔 돌아왔는데 카드가
옛 정류장을 계속 폴링하는 버그가 된다.

대응: 저장 시 `shared_preferences` 쓰기와 **동시에 `busSlotsProvider` state를 갱신**하고, 카드는
그 provider를 watch해 슬롯이 바뀌면 메모리 캐시를 버리고 새 `nodeId`로 폴링을 재시작한다.
위젯 테스트로 고정한다.

### 폴링 수명

- 주기 30초. 오늘 탭이 살아 있고 앱이 포그라운드일 때만.
- 백그라운드 진입 시 정지(`AppLifecycleListener`), 복귀 시 즉시 1회 조회 후 재개.
- 카드 provider는 `autoDispose` — `todayViewProvider`와 같은 이유다(이 앱은 `ShellRoute`라
  탭을 옮기면 화면이 dispose된다).

## 10. 범위에서 뺀 것

원본 6번의 "넣지 말 것"을 그대로 유지한다.

- **일정 장소 자동 버스 추천 / 출발시간 역산** — 원본 2단계. 길찾기 의존.
- **프록시 서버** — §5의 승격 조건을 만족하면 도입한다. 지금은 아니다.

원본 6번의 "여력되면" 항목 중 **저상버스 표시**(`vehicletp` → 아이콘 하나)는 Phase 3에서 여력이
