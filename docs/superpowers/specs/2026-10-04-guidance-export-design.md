# 지도 기록 내보내기 — 설계

날짜: 2026-10-04 · 선행: `2026-10-03-guidance-record-design.md`(지도 기록 탭 — 이 문서가 "다음 판"으로 미뤄 둔 PDF·원본 내보내기)

## 배경과 목표

지도 기록을 **학교 업무용 PC로 옮겨** 인쇄하고 공문에 첨부할 수 있게 한다(사용자 요청 2026-10-04).
휴대폰에서 다른 휴대폰으로 넘기는 기능이 아니다 — 인쇄와 공문 처리는 PC에서 한다.

제출 목적은 셋 다다(사용자 답):
- 교육활동 침해 신고·교권보호위원회 제출 — 원본과 해시까지 필요하다.
- 학교 내부 보고 — 인쇄한 PDF 한 부면 된다.
- 교실 안에서 끝난 일의 확인·보관 — 필요한 첨부만 골라 가볍게.

휴대폰 → PC 경로는 **카카오톡 나와의 채팅 · 메일 · 클라우드 드라이브**다(사용자 답). 세 경로 모두
파일 **하나**를 보내는 것이 가장 안정적이다. 앱은 공유시트까지만 맡고 경로는 사용자가 고른다.

성공 기준:
- PC에서 ZIP을 풀면 PDF와 원본이 한 폴더에 모이고, 파일 이름이 깨지지 않는다(Windows).
- PDF를 흑백으로 인쇄해도 읽히고, 사진도 함께 인쇄된다.
- 받는 사람이 PDF의 SHA-256과 원본을 대조할 수 있다.
- 서버 전송이 없다는 원칙이 그대로다.

## 결정 (사용자 선택, 2026-10-04)

| 질문 | 결정 |
|---|---|
| PDF 범위 | **최신 판 + 첨부 목록·해시.** 수정 사실은 처음 작성·마지막 수정 시각과 수정 횟수로만 적는다 |
| 내보내기 형태 | 시트 두 줄 — **`제출용 묶음(ZIP)`**(PDF + 원본) / **`PDF만`**(인쇄·내부 보고) |
| 첨부 선택 | 시트에 현재 첨부 체크 목록, **기본 전부 선택.** 확인용이면 필요한 것만 남긴다 |
| 뺀 첨부 | 내보내지 않는다(`removed_at`이 있는 첨부는 목록에도 없다) |
| 사진 인쇄 | PDF 뒤에 **붙임 페이지**로 한 쪽에 하나씩(축소본) |
| PDF 보호 | 암호 없음. 시트에 안내 한 줄 |
| 내보내기 단위 | 기록 한 건. 여러 기록 묶기·전체 백업은 미룬다 |
| PDF 생성 | Dart `pdf` 패키지로 기기 안에서(접근 A) |
| 보내는 방법 | 아이폰 `공유` / 안드로이드 `기기에 저장`(USB 케이블용) · `공유` |
| PC 안내 | 시트 안 접힌 `PC로 옮기는 방법`, 기기별 |

기각한 것:
- **두 버튼(PDF / 원본 여러 파일)** — 처음엔 골랐으나 PC가 목적지라는 기준으로 뒤집었다. 메신저로 파일을
  여러 개 보내면 PC에서 다시 모아 번호를 맞춰야 한다.
- **운영체제 인쇄 기능으로 HTML → PDF**(접근 B) — 두 플랫폼 결과가 갈리고 네이티브 코드가 생기며 위젯
  테스트로 못 잡는다.
- **화면 캡처 PDF**(접근 C) — 글자를 검색·복사할 수 없고 해시를 옮겨 적다 틀린다.
- **PDF 암호** — 비밀번호를 따로 전달해야 하고, 원본 녹음은 어차피 보호되지 않는다. 보호는 보내는 경로(학교 메일 등)가 맡는다.
- **관련인 이름 가리기** — 경과·들은 말 본문의 이름은 가리지 못해 불완전하다.
- **수정 이력 전체 수록** — 내부 보고용으로 무겁다. 이력은 앱 안 `수정 이력` 화면이 계속 보여 준다.
- **해시 사슬** — 지도 기록 설계에서 기각한 것을 이번에도 유지한다. 서버가 없어 외부 시각 증명을 붙일 수
  없고, 메일·메신저로 **제출한 시각 자체가 외부 기록** 역할을 한다.

## 화면과 흐름

- 기록 보기 앱바(`수정` 버튼 · 삭제 아이콘)에 공유 아이콘 하나를 더한다(`Icons.ios_share`,
  `Icon(semanticLabel: '내보내기')` — 코딩 규칙상 `tooltip`이 아니다).
- 누르면 하단 시트(`SheetTitle` `내보내기`). **위에서 무엇을 고르고, 아래 버튼으로 어떻게 보낼지 고른다.**
  1. **무엇을** — 선택 행 둘(하나만 고른다):
     - **`제출용 묶음(ZIP)`** — 부제 `PDF + 녹음 2개 · 사진 1개 원본`(선택 수로 조립). 첨부가 없으면 줄을 감춘다.
       첨부가 있으면 이것이 기본 선택이다.
     - **`PDF만`** — 부제 `인쇄·내부 보고용`. 첨부가 없으면 이것만 남는다.
  2. **첨부 체크 목록** — 현재 붙은 첨부마다 한 줄(종류 아이콘 · 녹음 길이/사진 크기 · 녹음·촬영 시각).
     기본 전부 선택. 첨부가 없으면 목록이 없다. `ZIP`을 골랐는데 선택이 0개면 보내기 버튼이 비활성이다
     (`PDF만`이면 0개도 된다 — 첨부 표와 붙임이 없는 PDF).
  3. **`PC로 옮기는 방법`** — 접힌 안내(아래 절).
  4. 안내 한 줄: `학생 이름과 기록 내용이 담깁니다. 받는 사람을 확인하세요.` — 이 시트가 확인 단계를 겸해 별도 확인 창은 없다.
  5. **어떻게** — 버튼:
     - 아이폰: **`공유`** 하나. 공유시트의 `파일에 저장`이 기기 저장 역할을 한다.
     - 안드로이드: **`기기에 저장`** · **`공유`** 둘. 안드로이드 공유시트에는 "파일로 저장"하는 공통 항목이 없어서,
       USB 케이블 경로를 위해 저장 위치 선택 창(SAF `ACTION_CREATE_DOCUMENT`)을 연다. 사용자가 `다운로드`를 고르면
       케이블로 PC에 꽂아 바로 복사할 수 있다.
     - 분기는 `isAndroid` 주입점(기본값 `Platform.isAndroid`)으로 한다 — `defaultTargetPlatform`은 테스트에서 항상 android다(코딩 규칙).
- `공유`: 임시 디렉터리에 파일을 만들고 `share_plus`로 공유시트를 연다. 공유시트가 닫히면(결과와 무관) 임시 파일을 지운다.
- `기기에 저장`: 바이트를 만들어 저장 창에 넘긴다(`file_picker`의 `saveFile`을 먼저 시험 — 이미 의존성에 있다).
  저장 창은 시스템 창이라 `SystemSheetGuard.run`으로 감싼다. 저장하면 `다운로드 폴더 등 고른 곳에 저장했어요` 스낵바, 취소하면 조용히 닫는다.
- 만드는 동안 버튼을 비활성화하고 진행 표시를 둔다(사진·녹음이 크면 몇 초 걸릴 수 있다). 실패하면 `내보내지 못했어요. 다시 눌러 주세요.` 스낵바 — **스낵바에 기록 내용을 넣지 않는다**(지도 기록 규칙: 스낵바는 잠금 덮개 밖에 뜬다).
- 대화상자·시트는 `useRootNavigator: false`(지도 기록 규칙 — 루트에 뜨면 잠금 덮개 위에 남는다).
- 잠금: 공유시트는 시스템 창이다. 15분 규칙이 그대로 적용된다. iOS에서 공유시트가 가림 면(`_veiled`)을 부르는지는 시뮬레이터에서 확인한다.
- `삭제한 기록` 화면에는 내보내기가 없다.

## PC로 옮기는 방법 (시트 안 접힌 안내)

학교 PC는 블루투스가 없거나 프로그램 설치가 막힌 경우가 많아, **어디서나 되는 경로를 먼저** 적는다.
Windows `휴대폰과 연결`·Quick Share는 PC 조건(블루투스·설치·같은 Wi-Fi)이 학교마다 달라 안내에 넣지 않는다
— 쓸 수 있는 사람은 공유시트에서 이미 보인다.

| 아이폰 | 안드로이드 |
|---|---|
| ① 메일 — `공유` → 메일 앱, PC에서 웹메일로 받기 | ① **USB 케이블** — `기기에 저장` → `다운로드`, PC에 꽂아 복사 |
| ② 카카오톡 나와의 채팅 — PC 카카오톡에서 받기 | ② 메일 |
| ③ 드라이브 — `파일에 저장`(iCloud Drive) 또는 구글 드라이브 앱, PC 브라우저에서 받기 | ③ 카카오톡 나와의 채팅 · ④ 드라이브 |

- 마지막 한 줄: `카카오톡·드라이브로 보내면 그 회사 서버에 파일이 남습니다.` (안드로이드는 `케이블로 옮기면 기기 밖 서버를 거치지 않습니다.`를 덧붙인다.)
- 아이폰에서 케이블은 쓰지 않는다 — Windows가 아이폰의 사진 폴더만 보여 줘 앱 파일을 꺼낼 수 없다.
- 위젯은 `ExpansionTile`, 배경·테두리는 `Material`이 진다(코딩 규칙: ListTile 위 색 컨테이너 금지).
  에듀파인 안내(`EdufineGuideSection`)처럼 **기기별로 자기 안내만** 보이고, 뼈대(번호 목록)는 같게 둔다.

## 파일 이름

메신저 목록에도 이름이 보이므로 **제목을 넣지 않는다**(학생 이름이 들어 있을 수 있다). 기록 시각
(`guidance_records.created_at`, 바뀌지 않는다)만 쓴다. 기본 이름 `20261004-1530`.

| 무엇 | 이름 |
|---|---|
| ZIP 파일 | `지도기록_20261004-1530.zip` |
| PDF만 | `지도기록_20261004-1530.pdf` |
| ZIP 안 PDF | `20261004-1530_record.pdf` |
| ZIP 안 원본 | `20261004-1530_01.aac` · `20261004-1530_02.jpg` … (번호 두 자리, 원래 확장자) |

- **ZIP 안의 이름은 영문·숫자·`-`·`_`·`.`만** 쓴다. ZIP 속 한글 이름은 Windows의 CP949와 UTF-8이
  어긋나 깨진 사례가 있다 — 이름에서 한글을 없애면 그 문제가 원천적으로 사라진다. ZIP 파일 자체의 이름은
  압축 밖(파일 시스템)이라 한글이어도 된다.
- 번호는 **선택한 첨부 안에서** `attached_at` 순으로 01부터 매긴다. PDF 첨부 표의 번호와 같다.
- 확장자는 저장된 `file_name`의 것을 그대로 쓴다(`.aac`·예전 `.m4a`·사진 확장자).
- 같은 분에 만든 기록 두 건이 있을 수 있지만 내보내기는 한 건씩이고 PC에서 폴더가 갈리므로 막지 않는다.

## PDF 구성 (A4, 흑백 인쇄 기준)

색 배경·색 글씨에 의미를 싣지 않는다. 칸 이름은 앱과 같은 `GuidanceStrings` 상수를 쓴다.

1. **머리** — `지도 기록` · 구분(`생활지도`/`교육활동 침해`) · 진행 상태(`진행 중`/`학교에서 마무리`/`교육청 이관`).
2. **기본 정보 표** — 제목 · 사건 시각(정밀도대로: 시각까지 / 날짜만 / `approx` 글) · 장소 · 관련인(이름을
   쉼표로) · 기록 시각(처음 작성) · 마지막 수정(`2026-10-05 09:12 · 수정 2회`, 수정이 없으면 `수정 없음`).
3. **본문** — `경과` · `들은 말` · `판단·조치`. 빈 칸은 생략한다. 긴 글은 쪽을 넘긴다.
4. **첨부 표**(선택한 첨부가 있을 때) — 번호 · 종류(녹음/사진, 앱에서 녹음/가져옴) · 파일 이름(ZIP 안 이름) ·
   길이 또는 크기 · 녹음·촬영 시각 · **SHA-256 64자리**(고정폭 글꼴, 줄바꿈 허용). 표 아래 두 줄:
   - `원본은 제출용 묶음(ZIP)에 같은 이름으로 들어 있습니다.` (`PDF만`이면 `원본은 앱에서 '제출용 묶음(ZIP)'으로 내보낼 수 있습니다.`)
   - `Windows에서 대조: certutil -hashfile 파일이름 SHA256`
5. **붙임 페이지** — 선택한 사진마다 한 쪽. 제목 `붙임 1 (첨부 02)`. PDF 안 사진은 축소본(긴 변 약 2000px,
   EXIF 방향 반영)이고 아래에 `PDF에 넣은 사진은 축소본입니다. 해시는 원본 기준입니다.`
6. **꼬리말** — `공직플랜에서 2026-10-04 15:30에 만듦 · 1/3쪽`.

녹음은 PDF에 넣을 수 없으므로 표에만 있다.

## ZIP 구성

- PDF + 선택한 원본. 원본은 **바이트 그대로**(재인코딩·리사이즈 없음) **store 방식**으로 넣는다 — 녹음·사진은
  이미 압축된 형식이라 다시 압축해 얻는 것이 없다.
- 폴더 없이 평평하게 둔다(압축을 풀면 `지도기록_20261004-1530` 폴더 하나가 생기는 것은 PC 압축 프로그램의 기본 동작).
- 녹음 원본은 변환하지 않는다. Windows 10·11 기본 플레이어가 `.aac`(ADTS)를 재생한다
  (Microsoft 지원 문서 "File types supported by Windows Media Player"). 변환하면 해시가 달라진다.

## 구조

feature-first, 빈 레이어 금지, 문자열은 `GuidanceStrings`.

| 단위 | 위치 | 역할 |
|---|---|---|
| 내보내기 목록 | `domain/guidance_export.dart` | **순수 함수.** 기록 시각 → 기본 이름, 선택된 첨부 → 번호·ZIP 안 이름·표 행. PDF와 ZIP이 **같은 목록**을 보므로 번호가 어긋날 수 없다 |
| PDF 생성 | `data/guidance_pdf_builder.dart` | 목록 + 최신 판 + 사진 바이트 + 폰트 → PDF 바이트. 화면·DB를 모른다 |
| ZIP 생성 | `data/guidance_zip_builder.dart` | PDF 바이트 + 원본 경로 → ZIP 바이트(store) |
| 시트 | `presentation/widgets/guidance_export_sheet.dart` | 체크 목록·두 줄·안내, 임시 파일 생성 → 공유 → 정리 |

- 새 의존성: `pdf`(PDF), `archive`(ZIP), 사진 축소·EXIF 회전에 `image`(아니면 `pdf`가 받는 형태로 다른 방법). 버전은 구현 때 `pubspec.lock`으로 확정해 CLAUDE.md 기술 스택 표에 적는다.
- 큰 파일 처리는 메인 isolate를 오래 막지 않도록 `compute`/`Isolate.run`을 검토한다(사진 여러 장 축소가 가장 무겁다).

### 첫 단계: 폰트 실험

앱 폰트는 `assets/fonts/PretendardVariable.ttf`(6.7MB, **가변 폰트**) 하나뿐이다. `pdf` 패키지는 가변 축을
다루지 않아 굵기가 고정되거나 기본 인스턴스 굵기가 예상과 다를 수 있고, 서브셋이 안 되면 PDF가 수 MB가 된다.
구현 계획의 **첫 작업**으로 측정한다: 한글 본문 · 굵은 제목 · 고정폭 해시가 제대로 나오는지, 한 쪽짜리 PDF 크기.
- 괜찮으면 그대로 쓴다.
- 안 되면 정적 Pretendard Regular·Bold(필요하면 KS X 1001 서브셋)를 추가하고 늘어나는 앱 용량을 사용자에게 보고한다.
- 해시용 고정폭 글꼴은 `pdf`의 내장 Courier(라틴 전용, 해시는 16진수뿐이라 충분)를 먼저 시험한다.

## 테스트와 가드

- `guidance_export_test.dart` — 기본 이름 형식, 선택 순서·번호(01부터, `attached_at` 순), 뺀 첨부 제외,
  **ZIP 안 이름이 `^[A-Za-z0-9._-]+$`**, PDF 표 행에 SHA-256 64자리가 그대로 들어감.
- `guidance_zip_builder_test.dart` — 실제로 만든 ZIP을 다시 풀어 **항목 이름 집합**과 **각 원본의 SHA-256이
  DB 값과 같은지**, store 방식인지 검사. 증거력과 PC 호환을 지키는 급소다.
- `guidance_pdf_builder_test.dart` — `%PDF` 머리, 쪽 수 = 본문 쪽 + 선택한 사진 수, 사진 없는 기록·빈 칸
  기록·긴 글 기록에서 예외 없음. PDF 안 글자는 압축돼 직접 검사가 어려우므로 **내용 검사는 목록 단계에서** 한다.
- 시트 위젯 테스트 — 기본 전부 선택·기본 ZIP, ZIP + 0개 선택이면 보내기 비활성, 첨부 없으면 ZIP 줄 없음,
  안내 한 줄 존재, 공유·저장 호출에 넘기는 파일 이름(공유·저장 함수는 주입점으로 바꿔 끼운다).
- 플랫폼 분기 — `isAndroid: true`면 `기기에 저장` + 안드로이드 안내만, `false`면 `공유` 하나 + 아이폰 안내만
  (아이폰 안내에 `케이블`이 없는지). 에듀파인 안내 가드처럼 한 테스트에서 두 번 그릴 때는 `key`를 준다.
- 기존 `guidance_isolation_test.dart`는 그대로 통과해야 한다 — 내보내기는 지도 기록 안에만 있다.
- 기존 시맨틱스 가드(이름 없는 `IconButton`·`tooltip` 금지)를 새 아이콘이 통과해야 한다.
- 에뮬레이터 확인(안드로이드): `기기에 저장` → `다운로드`에 파일이 생기는지(`adb shell ls`), 저장 창 뒤 잠금 상태.
- 시뮬레이터 확인: 공유시트 열림 · 가림 면 개입 여부 · 만든 PDF를 열어 한글·표·붙임 사진 · ZIP을 풀어 이름 확인.
  Windows에서 ZIP 풀기·녹음 재생은 사용자 PC 확인 항목이다.

## 개인정보처리방침

내보내기는 사용자가 직접 공유하는 기능이고 서버로 보내지 않으므로 수집 항목은 바뀌지 않는다.
§6에 `지도 기록은 사용자가 내보내기로 직접 공유할 때만 기기 밖으로 나갑니다` 한 줄을 더한다. 스토어 개인정보 라벨은 `수집 안 함` 유지.
