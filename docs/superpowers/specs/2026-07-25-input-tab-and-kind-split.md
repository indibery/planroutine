# 입력 탭 재편 + 업무/학교일정 분리

작성: 2026-07-25

## 왜

지금 검토 탭은 **검토가 주인공**이다. 검토가 끝나면 화면 전체가 "검토가 끝났어요"로 덮이고,
정작 다음에 할 일(새로 넣기)은 그 안에 갇힌다. 사용자가 자주 하는 동작은 검토가 아니라
**넣기**이고, 그중에서도 **월간 일정표 사진을 AI로 변환**하는 것이다.

그리고 지금은 모든 것이 한 종류다. 실제로는 성격이 다른 두 가지가 섞여 있다.

| | **업무** | **학교일정** |
|---|---|---|
| 뜻 | 내가 처리해야 하는 일 | 학교에서 일어나는 일 |
| 입력 | 작년 CSV(나이스·에듀파인 생산문서등록대장) | 월간 일정표 사진 → AI 변환 |
| 오늘 탭 | **표시됨** (체크·도장·진행 링) | 표시 안 됨 |
| 캘린더 탭 | 표시됨 | 표시됨 |
| 완료 개념 | 핵심 | 없음 |

오늘 탭의 도장·진행 링은 **업무에만** 의미가 있다. 학교일정을 섞으면 "운동회를 완료했다"가
되어 어색하다. 이 분리는 오늘 탭을 더 정확하게 만든다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 레이아웃 | **2안 왕복 흐름** — 사진 히어로 + `① 프롬프트 복사 → AI 앱 다녀오기 → ② 붙여넣기` |
| 주 경로 | **학교일정(사진 AI)** 히어로 · 업무(작년 CSV)는 보조 한 줄 |
| 탭 라벨 | `검토` → **`입력`** |
| 용어 | **일정 / 학교일정 / 업무**. "행사", "행사표"는 쓰지 않는다 |
| 오늘 탭 | **업무만** 표시 |
| 검토 흐름 | 업무·학교일정 **둘 다 검토 대기를 거친다** (AI 오인식을 사람이 걸러야 한다) |
| 일괄 등록 | **일괄 업무 등록 / 일괄 일정 등록**으로 나눈다 |
| 기존 데이터 | **전부 업무** (마이그레이션 기본값) |
| 검토 요약 | 대기 없으면 `검토 대기 없음 · 확정 N건` + 보기 링크 한 줄 |

## 도메인 모델

`kind`를 두 테이블에 넣는다. 두 입력 경로가 이미 같은 관문(`schedules.status = pending`)을
지나므로, 새 테이블 없이 컬럼 하나로 갈린다.

```
사진 → AI 변환 → schedules(kind=event,  pending) ─┐
작년 CSV      → schedules(kind=task,   pending) ─┼→ 검토 → 확정
                                                  └→ calendar_events(kind 승계)
                                                        ├→ 캘린더 탭: 둘 다
                                                        └→ 오늘 탭: kind=task만
```

### DB (v6 → v7)

```sql
ALTER TABLE schedules       ADD COLUMN kind TEXT NOT NULL DEFAULT 'task';
ALTER TABLE calendar_events ADD COLUMN kind TEXT NOT NULL DEFAULT 'task';
```

기본값 `task` 덕에 기존 사용자 데이터가 전부 업무가 된다(결정대로). 마이그레이션은
`DatabaseHelper._onUpgrade`에 `oldVersion < 7` 분기로 추가.

### 도메인 타입

`lib/features/schedule/domain/entry_kind.dart`

```dart
enum EntryKind {
  task,   // 업무 — 내가 처리할 일. 오늘 탭에 뜬다.
  event;  // 학교일정 — 학교에서 일어나는 일. 캘린더에만.
}
```

`Schedule`·`CalendarEvent`에 `kind` 필드 추가(기본 `task`), `fromMap`/`toMap` 반영.

## 화면

### 입력 탭 (2안)

```
── 대기 있음 ──
[INPUT / 입력]
┌────────────────────────────────┐
│ 📷 학교일정 사진으로 넣기         │
│    월간 일정표를 AI에게 맡기세요   │
│ [① 프롬프트]›[AI 앱 다녀오기]›[② 붙여넣기] │
└────────────────────────────────┘
  ⭳ 작년 업무 가져오기 (에듀파인 CSV) ›
─────────────────────────────────
검토 대기 12건              137/149 · 92%
[전체 12] [업무 8] [학교일정 4]
← 삭제  |  확정 →
  3월
  ○ [업무] 1차 학급편성 결과 제출
  ○ [일정] 과학의 달 행사
  …
[ 일괄 업무 등록 8건 ]  [ 일괄 일정 등록 4건 ]

── 대기 없음 ──
(위 입력 영역 동일)
─────────────────────────────────
검토 대기 없음                확정 149건
        확정됨 149건 보기 ›
```

- **화면 제목은 `입력`** — 이 탭은 업무와 학교일정을 **둘 다** 넣으므로 "일정 입력"이라 하면
  업무가 빠진다. eyebrow는 `INPUT`.
- AppBar 우측 가져오기 아이콘은 **제거**(본문 보조 링크와 중복).
- 검토 행에 **종류 배지**(`업무` / `일정`)를 붙여 무엇을 확정하는지 보이게 한다.
- **일괄 등록을 종류별로 분리** — 한 번에 확정할 때 성격이 다른 것이 섞이지 않게 한다.
  기존 `대기 N건 확정` pill을 `일괄 업무 등록 N건` / `일괄 일정 등록 N건` 두 개로.
  해당 종류의 대기가 0이면 그 pill은 숨긴다.
- 필터 줄에 종류 필터(`업무` / `학교일정`)를 카테고리 필터와 함께 둔다.

### 오늘 탭

`buildTodayView`가 **업무만** 담는다 — 순수 함수에 필터 한 줄:

```dart
events.where((e) => e.kind == EntryKind.task)
```

지난 항목·오늘 항목·진행도 모두 업무 기준. 학교일정은 오늘 탭에 나타나지 않는다.

### 캘린더 탭

둘 다 표시하되 리스트에서 구분한다. 월 그리드의 점은 **이번 범위에서 건드리지 않는다**
(색 규칙이 이미 복잡하다 — 골드는 오늘·중요, 붉은색은 공휴일·일요일, 파랑은 토요일·이벤트).

- 이벤트 타일에 `학교일정`은 회색 pill 배지. 업무는 배지 없음(기본).

## 테스트

**유닛**
- `EntryKind` 직렬화 왕복, 모르는 값 → `task` 폴백
- `buildTodayView`가 학교일정을 제외한다 / 진행도에도 세지 않는다
- 마이그레이션: v6 DB에 `kind` 컬럼이 붙고 기존 행이 `task`가 된다

**위젯**
- 검토 행의 종류 배지
- 일괄 등록 pill이 종류별로 나뉘고, 해당 종류 대기가 0이면 숨는다
- 입력 탭: 히어로 3단 흐름 · 보조 링크 · 대기 없을 때 한 줄 요약
- 캘린더 리스트의 학교일정 배지

**기존 테스트 갱신 필요**
- `schedule_screen_review_test.dart` — 완료 상태·필터 줄·확정 pill 구조가 바뀐다
- `today_view_test.dart` — 이벤트에 `kind`가 붙는다(기본 task라 대부분 그대로 통과)

## 단계

범위가 커서 셋으로 나눈다. 각 단계가 끝날 때마다 배포 가능한 상태가 된다.

| 단계 | 내용 | 왜 이 순서 |
|---|---|---|
| **1** | `kind` 도입 · DB v7 · 오늘 탭 업무만 · 검토 행 배지 | 데이터 정합성이 먼저다. UI를 먼저 바꾸면 잘못된 데이터를 예쁘게 보여주게 된다 |
| **2** | 입력 탭 재편(2안) · 탭 라벨 `입력` · 일괄 등록 분리 · 용어 통일 | 1이 끝나야 종류별 UI를 만들 수 있다 |
| **3** | 스토어 설명·심사 메모·CLAUDE.md 갱신 | 사용자에게 보이는 글은 기능이 확정된 뒤에 |

## 범위 밖

- 일정/업무를 손으로 직접 추가하는 UI (결정: 넣지 않음)
- 월 그리드 점의 종류별 색 구분
- 학교일정의 완료 체크
- 종류 간 전환(업무 → 학교일정으로 바꾸기)
- 반복 일정
