# 지도 기록 글로 보기(참고용 전사) · 녹음만 공유 — 설계

날짜: 2026-10-07 · 선행: `2026-10-03-guidance-record-design.md`(지도 기록 탭) ·
`2026-10-04-guidance-export-design.md`(내보내기 시트)

## 배경과 목표

1.4.0 출시 뒤 "녹음 내용을 외부 AI 없이 기기에서 글로 바꿀 수 있나"는 문의가 들어왔다(2026-10-07).
같은 자리에서 사용자가 하나를 더 요청했다: 지금은 내보내기가 ZIP·PDF뿐이라 **녹음만 따로 보낼 길**이 없다.

### 사전 조사 (2026-10-07)

| 선택지 | 판단 |
|---|---|
| iOS `SpeechAnalyzer` + `SpeechTranscriber` (iOS 26+) | **채택.** 기기 안에서만 처리, 한국어 지원, 긴 녹음용. 모델은 OS가 받아 관리해 앱 용량이 늘지 않는다 |
| iOS `SFSpeechRecognizer` | 기각 — 한 번에 1분 제한 |
| Android ML Kit GenAI Speech Recognition | 보류 — alpha, 파일 입력은 **실시간 속도로 흘려 넣어야** 해서 1시간 녹음 = 1시간 |
| Android `SpeechRecognizer` + `EXTRA_AUDIO_SOURCE` | 보류 — 파일 입력 지원이 인식기 구현마다 다르다 |
| Whisper(whisper.cpp·sherpa-onnx 내장) | 기각 — 모델 60~570MB, 중저가 기기에서 느림, 한국어 환각 보고 |

`SpeechTranscriber`는 **iPhone 11·SE 2세대에서 `isAvailable == false`** 다(Neural Engine 요구, Apple 포럼).

### Mac 실측 (macOS 27.0.1, 같은 Speech 프레임워크)

- **형식**: 앱 녹음 형식(ADTS AAC 모노 44.1kHz 64kbps)과 음성 메모 `.m4a`를 변환 없이 읽었다.
- **속도**: 합성 대화 67초 → 0.88초(실시간 77배), 실제 녹음 12분 38초 → 6.7초(113배).
- **합성 음성**(또렷한 한 목소리): 문장은 거의 정확. 뜻이 바뀌는 오류(`세게` → `3개`), 높임말 소실(`찾아뵐게요` → `찾아볼게요`),
  **같은 이름이 실행마다 다르게** 나옴(`서연`/`서현`).
- **실제 상담 녹음**(교사가 휴대폰 가까이, 학생은 멀고 작게): 교사의 말은 요지가 살아 있다. **학생의 말은 대부분 빠지거나
  뜻이 통하지 않는다** — 10~15초 동안 글이 없는 구간이 여러 번 나왔다.
- **화자 구분이 없다.** 두 사람의 말이 한 문단에 붙는다.

지도 기록에서 가장 중요한 것은 대개 상대방의 말인데 바로 그것을 가장 많이 놓친다. 그래서 이 기능은
**"대화를 훑어보고 다시 들을 곳을 찾는 참고용"** 으로 위치를 잡는다. 발언 기록을 대신하지 않는다.

### 성공 기준

- 지원 기기에서 녹음 하나를 눌러 1분 안에 시각이 붙은 글을 보고, 그 시각부터 녹음을 다시 듣는다.
- 글이 빠진 구간이 화면에서 드러나 그 자리를 바로 들어 볼 수 있다.
- 녹음은 기기 밖으로 나가지 않는다. 전사문은 저장되지 않는다.
- 녹음 원본을 ZIP 없이 한 파일 그대로 보낼 수 있고, SHA-256이 첨부 정보와 같다.

## 결정 (사용자 선택, 2026-10-07)

| 질문 | 결정 |
|---|---|
| 플랫폼 | **iOS 전용**(26+ · `isAvailable`). 안드로이드는 버튼을 숨긴다 |
| 전사문 저장 | **저장하지 않는다.** 열 때마다 새로 전사한다(DB 변경 없음) |
| 화면에서 할 수 있는 것 | 시각을 누르면 그 위치부터 재생 + 글 복사 |
| 화면 모양 | **B안** — 위 플레이어 + 문단 카드(카드마다 `복사`) + 앱바 `전체 복사` |
| 글 없음 구간 | 표시한다 — 눌러서 그 위치부터 듣는다 |
| 버튼 이름 | **`글로 보기`** + `참고용` 꼬리표 |
| 녹음만 공유 위치 | 내보내기 시트에 세 번째 선택지 **`녹음만`** |
| 구현 방식 | 앱 타깃에 Swift 직접(접근 A) — 패키지 미사용 |

시안: Claude 디자인 캔버스 `지도 기록 전사 화면`(https://claude.ai/artifact/4jg53HZeUtQ5LZDrzaP2Bc) — ① 진입점 ·
③ B안(채택) · ④ 전사 중 · ⑤ 내보내기 녹음만. ② A안은 기각.

기각한 것:
- **DB에 저장** — 스키마 v11, 휴지통·초기화·내보내기·잠금과의 관계를 전부 정해야 한다. 전사가 실시간 100배 안팎이라
  다시 만드는 비용이 작다. 대가: 목록에서 전사문으로 검색할 수 없고, 1시간 녹음은 열 때마다 30초 안팎을 기다린다.
- **전사문을 사실·발언 칸에 자동으로 넣기** — 틀린 이름·발언이 판(추가만)에 영구히 남는다. 옮기는 것은 교사가 듣고 고른 뒤 손으로 한다.
- **패키지(pub.dev)** — 나온 지 얼마 안 됐고 파일 전사·시각 지원이 확인되지 않았다. 단축어 기능과 같은 이유로 앱 타깃에 둔다.
- **A안(시각 열 + 아래 플레이어)** — 촘촘하지만 문단 복사가 길게 누르기뿐이다.
- **녹음 줄마다 공유 버튼** — 보내는 길이 두 곳으로 나뉜다.

## 구조

```
[기록 보기] 녹음 첨부 줄 ─ "글로 보기 · 참고용" (지원할 때만)
      │ push  /guidance/record/:id/transcript/:attachmentId   (지도 기록 중첩 셸 안 — 잠금 그대로)
      ▼
[글로 보기 화면]
      │  TranscriptionService (Dart 인터페이스)
      │      isAvailable() → bool
      │      transcribe(path) → Stream<TranscriptSegment{startMs, endMs, text}>
      │            ▲
      │            │ MethodChannel `planroutine/transcriber` + EventChannel(문단 흘려 보내기)
      │            ▼
      │  ios/Runner/Transcriber.swift  (if #available(iOS 26, *))
      ▼
  buildTranscriptView(segments)  → 문단 카드 + 글 없음 줄   (순수 함수)
```

### Swift (`ios/Runner/Transcriber.swift`)

- `isAvailable`: `#available(iOS 26, *)` 이고 `SpeechTranscriber.isAvailable` 이고 `supportedLocale(equivalentTo: ko-KR)`가 있을 때만 true.
- `transcribe(path)`: 한국어 모델이 없으면 `AssetInventory`로 내려받고(처음 한 번), `AVAudioFile`로 열어 `analyzeSequence`로 전사한다.
  확정 결과(`reportingOptions: []`)만 문단 하나씩 이벤트로 보낸다. `attributeOptions: [.audioTimeRange]`로 시작·끝 시각을 얻는다.
- 취소: Dart가 구독을 끊으면 Swift `Task`를 취소한다(화면을 떠나면 멈춘다).
- 오류 코드: `modelDownloadFailed` · `fileNotFound` · `unsupported` · `failed`. 메시지에 파일 경로·내용을 넣지 않는다.
- 채널 배선은 기존 채널과 같은 자리(`didInitializeImplicitFlutterEngine`)다. 앱 최소 버전 16.0은 그대로 둔다.
- 파싱·표시 규칙은 Dart가 진다. Swift는 엔진 결과를 그대로 넘긴다(단축어 기능의 "Swift는 채널 호출만" 원칙).

### Dart

- `TranscriptionService` 인터페이스 + `ChannelTranscriptionService` 구현. 위젯 테스트는 가짜 구현을 끼운다(`AudioPlayback`과 같은 패턴).
- `transcriptAvailableProvider`(FutureProvider): 안드로이드면 채널을 부르지 않고 false. 플랫폼 판정은 주입점(`Platform.isAndroid` 기본)으로 둔다.
- `buildTranscriptView(List<TranscriptSegment>, {gapThreshold = 8초})` → `[Paragraph | Gap]`.
  Gap = 앞 문단 끝과 다음 문단 시작 사이가 8초 이상. **녹음 맨 앞의 빈 구간도** 첫 문단 시작이 8초 이상이면 Gap으로 보인다.
- `formatTranscriptForCopy(segments)` → `[MM:SS] 글` 줄을 빈 줄로 잇는다(전체 복사). 1시간 넘으면 `H:MM:SS`.
- `AudioPlayback`에 `seek(Duration)`을 더한다(`JustAudioPlayback`은 `_player.seek`).

## 글로 보기 화면 (B안)

- 앱바: 뒤로 · `글로 보기` + `참고용` 꼬리표 · `전체 복사`(전사가 끝나기 전에는 꺼짐).
- 위: 플레이어 카드(재생/멈춤 · 진행 막대 · 현재/전체 시각). 화면에 하나뿐이다.
- 안내 한 줄: `작은 목소리는 빠지거나 틀릴 수 있어요. 기록에 옮기기 전에 들어 보세요.`
- 문단 카드: 시각 칩(누르면 그 위치부터 재생) + `복사`(그 문단 글만) + 글. 재생 위치가 들어 있는 카드는 골드 테두리
  (`goldFill`), 그 칩은 골드 채움 + 멈춤 모양. 색만으로 두지 않는다(칩 모양이 바뀐다).
- 글 없음 줄: 옅은 실선 테두리 버튼 `MM:SS · N초 글 없음 · 들어 보기`(1분 넘으면 `21분`·`1분 30초`) — 누르면 그 위치부터 재생.
  (1.4.2에서 바꿈: 처음엔 점선·`…부터 N초 동안 글이 없어요` 문구였다. 점선은 Flutter에 기본이 없어 실선을 유지하기로 했다 — 사용자 결정 2026-10-09.)
- 전사 중: 위에 `받아 적는 중… 04:10 / 12:38` 진행 막대 + `이 화면을 닫으면 멈춰요. 녹음은 휴대폰 밖으로 나가지 않아요.`
  문단이 나오는 대로 아래에 쌓인다. 진행은 마지막 문단의 끝 시각 / 녹음 길이.
- 모델 준비 중(처음 한 번): `한국어 음성 인식 모델을 준비하는 중이에요. 처음 한 번 Apple에서 내려받아요.`
- 복사 뒤 스낵바 `복사했어요`. **스낵바에 글 내용을 넣지 않는다**(잠금 덮개 밖에 남는다 — 기존 규칙).
- 수명: 화면을 떠나면 전사 취소·재생 멈춤. 앱이 `resumed`가 아니게 되면 재생만 멈춘다(첨부 줄과 같은 규칙).

| 상황 | 문구 | 동작 |
|---|---|---|
| 첫 사용, 모델을 못 받음(오프라인 등) | `처음 한 번은 인터넷 연결이 필요해요` | `다시 시도` |
| 녹음 파일 없음 | 기존 `GuidanceStrings.attachmentMissing` | 없음 |
| 문단 0개 | `받아 적을 말소리를 찾지 못했어요` | 없음 |
| 그 밖의 실패 | `글로 바꾸지 못했어요` | `다시 시도` |

전사 도중 실패하면 이미 받은 문단은 남기고 실패 줄을 아래에 붙인다.

### 진입점

- 기록 보기의 녹음 첨부 줄 아래에 `글로 보기 · 참고용` 버튼(높이 44, `surfaceVariant` 채움). 편집 화면의 첨부 줄에는 두지 않는다.
- `transcriptAvailableProvider`가 true이고 파일이 있을 때만 보인다(파일이 없으면 숨긴다).
- `ButtonSemantics`로 감싸 시뮬레이터 자동화가 읽을 수 있게 한다(리포 규칙).

## 녹음만 공유

- `ExportKind.audioOnly`. 시트의 선택지 순서: `제출용 묶음(ZIP)` · **`녹음만`** · `PDF만`.
  부제 `원본 파일 그대로 · 받는 쪽에서 바로 들을 수 있어요`.
- 선택지는 **파일이 있는 녹음이 하나 이상일 때만** 보인다. 고르면 사진 줄은 꺼지고 부제가 `녹음만 보낼 때는 빠져요`가 된다.
  고른 녹음이 0개면 보내기 버튼이 꺼진다.
- **파일을 메모리에 읽지 않는다.** 임시 폴더(`guidance_export/`)로 `File.copy`해 새 이름을 붙이고 공유한 뒤 지운다 —
  1시간 녹음도 메모리를 쓰지 않는다. 바이트가 같으므로 첨부 정보의 SHA-256과 대조된다.
- 파일 이름: `지도기록_<yyyyMMdd-HHmm>_<NN><ext>`(예: `지도기록_20261004-1530_01.aac`). `NN`은 **고른 녹음 사이의 순번**,
  `ext`는 기존 `_safeExt` 규칙. 제목은 넣지 않는다(기존 규칙).
- 여러 개면 공유시트 한 번에 함께 보낸다(`shareXFiles`).
- 안드로이드 `기기에 저장`은 **녹음 1개일 때만** 켠다. 2개 이상이면 버튼을 끄고 `여러 개는 공유로 보내 주세요`를 보인다
  (SAF 저장 창은 한 번에 파일 하나).
- `ExportOutput`이 바이트 하나를 들던 구조라, 녹음만은 별도 경로(`buildAudioOnly` → 파일 목록)로 둔다. ZIP·PDF 경로는 손대지 않는다.

## 손대지 않는 것

- DB 스키마(v10 그대로) · 판·첨부 테이블 · SHA-256 체계 · ZIP·PDF 생성.
- 개인정보처리방침 — 녹음은 여전히 기기 밖으로 나가지 않는다. 내려받는 것은 Apple 음성 모델뿐이다.
- 안드로이드 전사 — 위 조사 표의 보류 사유가 풀리면(ML Kit 정식·파일 입력 제약 해제) 다시 본다.
- 화자 구분 — Apple API에 없다.

## 검증

- 유닛: `buildTranscriptView`(8초 경계 · 맨 앞 빈 구간 · 0개) · `formatTranscriptForCopy`(시 단위) · 녹음만 파일 이름·순번·확장자.
- 위젯(가짜 `TranscriptionService`): 문단이 하나씩 쌓임 · 전사 중 `전체 복사` 꺼짐 · 실패/빈 결과/모델 실패 문구와 `다시 시도` ·
  시각 칩 → `seek` 호출 · 미지원·안드로이드·파일 없음에서 `글로 보기` 숨김 · 스낵바에 글 내용 없음.
- 내보내기 시트: `녹음만`이 녹음 0개면 안 보임 · 고르면 사진 줄 꺼짐 · 안드로이드 2개 이상이면 저장 꺼짐 · 공유에 넘긴 파일의
  바이트가 원본과 같음.
- 가드: 채널 이름이 Swift·Dart 양쪽에서 같다 · Swift에 `#available(iOS 26` 분기 · 앱 타깃(pbxproj)에 `Transcriber.swift` 등록 ·
  배포 타깃 16.0 유지(기존 `ios_deployment_target_test.dart`).
- 시뮬레이터: 앱 녹음은 무음이므로 오디오 파일을 **가져오기**로 붙여 확인한다.
  ⚠️ **`SpeechTranscriber`가 시뮬레이터에서 도는지 모른다** — 구현 계획의 첫 작업으로 확인한다. 안 되면 전사 결과는
  TestFlight 실기기에서 사용자가 확인하고, 시뮬레이터는 미지원 경로(버튼 숨김)와 화면 흐름만 본다.
- 확인 결과(2026-10-07, iPhone 17 / iOS 27.0 시뮬레이터, `simctl spawn`으로 같은 코드 실행): **`SpeechTranscriber.isAvailable == false`** —
  전사 결과는 실기기 몫이다. 시뮬레이터에서는 버튼이 숨는 경로와 녹음만 공유를 본다(Mac에서는 같은 코드가 돈다).
