# 기능 모듈 — 고정 탭 + 사용자가 켜는 선택 기능

**2026-10-02**

## 개요

앞으로 추가할 기능(첫 후보: 시간표)을 **필요한 사람만 켜서 쓰게** 한다. 기능은 계속
늘어날 수 있으므로, 탭 목록을 상수에서 **기능 등록부**로 바꾸고 사용자가 설정에서
켜고 끄고 순서를 바꾸게 한다. 목표하는 느낌은 "나만의 캘린더 앱스토어"다.

**성공 기준**: 새 기능을 만들 때 **등록부에 한 항목만 더하면** `기능 관리` 화면에
나타나고, 사용자가 켜면 제자리(탭 또는 오늘 탭 카드)에 나타난다.

### 이번 범위

- 기능 등록부, 설치 상태 저장, 정리 규칙(순수 함수)
- `기능 관리` 화면(스위치 + 탭 순서 변경)
- 출퇴근 버스 카드를 등록부로 이전
- 탭형 경로는 **테스트용 기능**으로만 검증한다

### 범위 밖

- **시간표 자체.** 데이터 모델·화면·입력 방식이 필요한 별도 기능이라 다음 스펙에서 다룬다.
  시간표를 만드는 순간이 위 성공 기준을 실제로 시험하는 순간이다.
- 오늘 탭 카드끼리의 순서 변경. 카드가 둘 이상 생길 때 추가한다.
- 한 기능이 탭과 카드를 동시에 갖는 것(결정 1의 C안). 등록부 구조가 바르면 나중에 넓힐 수 있다.
- **아이폰 단축어(App Intents) 경로.** 이 작업은 그 경로를 건드리지 않는다(아래 "건드리지 않는 것").

### 배포 시점

버스 하나만 있는 `기능 관리` 화면은 빈약해 보인다. **첫 배포는 시간표가 완성된 뒤 함께
하는 편이 자연스럽다**(사용자와 공유한 판단이며, 배포 시점에 다시 정한다).

## 결정 기록

브레인스토밍에서 사용자가 고른 것과 그 이유.

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| 1 | 기능이 화면에 들어오는 형태 | **탭 또는 오늘 탭 카드** 중 하나 | 버스 카드라는 선례가 이미 있다. 탭만 허용하면 6개 상한에 금방 닿는다 |
| 2 | 고정할 것 | **기존 4탭 모두 숨길 수 없음, 순서는 자유, 설정은 맨 끝 고정** | 오늘 탭은 카드의 집이라 못 숨긴다. 입력은 넣기의 유일한 입구, 설정은 되돌아오는 길, 캘린더는 앱의 정체성 |
| 3 | 탭이 넘칠 때 | **상한 6개, 넘으면 켜기를 막고 안내** | 지금 계획된 탭형 기능은 하나뿐이다. `더보기`·"설치/고정 분리"는 아직 오지 않은 문제다 |
| 4 | 범위 | **틀 + 버스 이전까지** | 빈 시간표 탭을 배포하면 켰는데 아무것도 없는 화면이 된다 |
| 5 | 설치 상태의 주인 | **등록부 한 곳** | 기능마다 자기 켜기를 두면 탭 순서와 상태가 두 곳으로 갈라진다 |
| 6 | 켜기·끄기 조작 | **스위치**(추가/빼기 버튼 아님) | 버튼은 누르면 항목이 다른 섹션으로 옮겨 가 사라진다. 스위치는 제자리에 머문다(오늘 탭 완료 토글의 자리 고정과 같은 원칙) |

## 구조

### 기능 정의 — `AppModule`

```dart
AppModule(
  id: 'bus',                 // 저장되는 값. 한번 배포하면 바꾸지 않는다
  name: '출퇴근 버스',
  description: '오늘 탭 맨 위에 버스 도착 시간을 보여줘요',
  icon: Icons.directions_bus_outlined,
  placement: ModulePlacement.todayCard,   // tab | todayCard
  fixed: false,
)
```

- 탭형 기능은 라우트·아이콘(선택/비선택)·라벨을 함께 갖는다. 지금 `MainShell._tabs`의
  레코드가 담는 것과 같다.
- 카드형 기능은 오늘 탭에 넣을 위젯 빌더를 갖는다.
- 문자열(이름·설명)은 리포 규칙대로 `*Strings`에 둔다. **id는 `*Strings`에 두지 않는다** —
  UI 문자열이 아니라 저장값이다(Android 알림 채널 id와 같은 이유).

### 등록부 — `moduleCatalog`

- 위 상수들의 목록이다. 오늘·캘린더·입력·설정은 `fixed: true`인 탭, 버스는 카드.
- **provider로 한 번 감싼다**(`moduleCatalogProvider`). 테스트가 탭형 테스트용 기능을
  override로 주입해야 하기 때문이다 — 실제 탭형 기능이 아직 없다.
- 자리는 `lib/core/modules/`다. `shared/widgets/`는 `features/`를 import하지 않는다는 규칙이
  있고, `core/router`가 이미 feature 화면을 import하므로 같은 방향이다.

### 저장 — `installed_modules_v1`

- shared_preferences 키 하나에 **id 목록**을 JSON으로 저장한다. 목록 순서가 곧 탭 순서다.
- 고정 탭의 순서도 이 목록이 담는다(고정 = 숨길 수 없음이지 순서 고정이 아니다).

### 정리 규칙 — `resolveModules` (순수 함수)

저장값을 그대로 믿지 않고 **항상** 이 함수를 거친다.

1. 고정 탭은 저장값에 없어도 포함한다(빠진 것은 기본 순서 자리에 넣는다).
2. 설정은 항상 맨 끝이다.
3. 등록부에 없는 id(나중 버전에서 사라진 기능)는 조용히 버린다.
4. 중복 id는 첫 등장만 남긴다.
5. 탭이 6개를 넘으면 설정을 지킨 채 뒤쪽 선택 탭부터 잘라 낸다.
6. 저장값이 없거나 깨져 있으면 기본값(오늘·캘린더·입력·설정, 카드 없음)이다.

`computeNotifications`·`buildTodayView`와 같은 패턴으로, 단위 테스트의 중심이 된다.

### 탭바 — `MainShell`

- 상수 `_tabs` 대신 **탭 목록을 인자로 받는다.** 라우터의 `ShellRoute` builder가 provider를
  읽어 넘긴다. 그래서 `MainShell`은 계속 feature를 모른다.
- `indexForLocation(location, {tabs})`의 `tabs` 기본값은 지금의 4탭이다 — 기존 테스트
  (`main_shell_tab_index_test.dart`)의 호출이 그대로 동작한다.
- `_pushOwner`의 주인 탭이 목록에 없으면 -1을 그대로 쓰지 않고 **설정 탭의 인덱스**를 돌려준다.
  설정은 항상 있고 push 화면의 대부분이 설정 소속이라 가장 덜 어긋난다.
  지금은 주인이 전부 고정 탭이라 일어나지 않지만, 선택 기능 탭이 push 라우트를 가지면 생긴다.

### 라우트

- 탭형 기능의 라우트는 **설치 여부와 무관하게 항상 등록**한다. 꺼 둔 기능의 주소로 들어가도
  Page Not Found가 뜨지 않고, 설치 상태가 바뀔 때 라우터를 다시 만들 필요가 없다.
- 시작 화면(`/today`)과 온보딩 종료(`/calendar`)는 둘 다 고정 탭이라 바꾸지 않는다.

### 오늘 탭 카드

- `TodayBody`의 `busCard` 자리 하나를 `cards` 목록으로 바꾼다. 설치된 카드형 기능을
  저장 목록 순서대로 넣는다.

## `기능 관리` 화면

**진입점**: 설정 탭에 `기능` 섹션을 새로 두고 `기능 관리 … N개 사용 중 ›` 한 줄. 누르면
`/modules`로 push(버스 상세 설정과 같은 패턴). `_pushOwner`에 `/modules → /settings`를 넣는다.

```
내 탭                              5/6
 ≡  오늘          🔒
 ≡  캘린더        🔒
 ≡  입력          🔒
 ≡  시간표
    설정          🔒  (맨 끝 고정, 드래그 없음)

기능
 ┌──────────────────────────────┐
 │ 📅 시간표        탭    [ ●] │
 │ 요일별 수업을 한눈에 봐요     │
 ├──────────────────────────────┤
 │ 🚌 출퇴근 버스  오늘 카드 [ ●] │
 │ 오늘 탭 맨 위에 도착 시간을…  │
 └──────────────────────────────┘
```

- **내 탭**: 켜진 탭만 `ReorderableListView`로 보여 주고 순서만 바꾼다. 고정 탭에는 자물쇠,
  설정 행은 드래그 불가로 맨 아래.
- **기능**: 고정이 아닌 기능 **전부**를 켜짐 여부와 무관하게 같은 자리에 둔다. 카드마다
  아이콘·이름·자리(`탭`/`오늘 카드`)·한 줄 설명·스위치.
  - 탭형 기능을 켜면 내 탭의 설정 바로 앞에 들어간다.
  - 탭이 6개면 꺼져 있는 탭형 기능의 스위치를 비활성화하고 카드 아래에
    `탭이 가득 찼어요 (6/6)`를 적는다. 카드형은 상한과 무관하다.
- **끄더라도 데이터는 남긴다.** 버스를 꺼도 정류장·시간대는 지우지 않아 다시 켜면 그대로다
  (`aiTaskShareEnabledProvider`를 남겨 둔 것과 같은 원칙). 잃는 것이 없으므로 확인
  다이얼로그를 띄우지 않는다.
- **기능별 설정은 켜져 있을 때만 보인다.** 설정 탭의 `버스 도착` 행은 버스가 켜져 있을 때만
  나타난다. 켠 직후의 안내는 오늘 탭 카드의 기존 빈 상태가 맡는다.
- 스위치는 전역 `switchTheme` 색 가드를 그대로 따른다.

## 버스 이전

### 일회성 이전

앱 시작 시 `installed_modules_v1`이 **아직 없으면** 한 번만 실행한다.

- `bus_settings_v1`의 `enabled`가 `true`면 설치 목록에 `bus`를 넣고 저장한다.
- 판정 기준이 "키가 있는가" 하나라 같은 사용자를 두 번 이전하지 않는다.
- 꺼 둔 사용자·신규 사용자는 버스가 꺼진 채로 시작한다 — 지금과 화면이 같다.

### `enabled` 필드 은퇴

- `BusSettings`에서 `enabled`를 뺀다. 남겨 두면 누군가 다시 그 값으로 분기를 짠다.
  이전 함수만 원본 JSON에서 이 값을 직접 읽는다.
- `BusCardHost`의 검사 세 곳(`bus_card_host.dart:213`·`:304`·`:363`)을 없앤다. 카드는
  설치돼 있을 때만 올라오므로 올라와 있다는 사실이 곧 켜짐이다.
- 버스 상세 설정의 마스터 스위치(`bus_settings_tiles.dart:51`)를 없앤다. 그 자리에 안내를
  둘지는 구현 때 화면을 보고 정한다.
- `buildBusSettingsSummary`의 `꺼짐` 분기를 없앤다 — 꺼져 있으면 그 행이 안 보인다.

### 테스트는 줄이지 않고 다시 겨눈다

`enabled`를 참조하는 테스트 7개 파일(`bus_card_host_test`·`bus_card_host_move_test`·
`bus_settings_provider_test`·`bus_settings_summary_test`·`bus_settings_tiles_test`·
`bus_slot_tile_long_name_test`·`domain/bus_settings_test`)은 **같은 의도를 새 진실
공급원으로** 검사하게 고친다. 예: `enabled: false면 카드가 없다` →
`버스가 설치되지 않았으면 오늘 탭에 카드가 없다`. 선언 수는 줄이지 않는다
(`protect-tests.sh`가 막는다). `test/tools/visual_check.dart`도 `enabled`를 쓰므로
`flutter analyze`로 확인한다.

## 건드리지 않는 것

- **아이폰 단축어(App Intents).** 등록은 `intakeAiScheduleText`로 확정·캘린더에 넣고
  `schedulesProvider`를 무효화하며, 조회는 `buildScheduleDigest`를 쓴다. 이 작업은 그
  경로 어디에도 닿지 않는다. 단축어는 **보류 중**이며 보류 기록은
  `2026-09-13-ios-app-intents-design.md`의 마지막 절에 있다 — 이 작업 중 그 코드와 가드
  (`app_intents_wiring_test.dart` 등)를 정리 대상으로 보지 말 것.
- 알림, 캘린더 연동, 공휴일 등 탭 안의 기능.

## 테스트와 검증

### 단위 (순수 함수)

- `resolveModules`: 위 정리 규칙 6개 각각.
- 버스 이전: 켜 둔 기존 사용자 → 설치 / 꺼 둔 기존 사용자·신규 → 미설치 /
  이미 이전함 → 재실행 안 함 / `bus_settings_v1` 깨짐 → 미설치.
- `indexForLocation`: 순서가 바뀐 탭, 선택 기능 탭, 주인 탭이 목록에 없는 push 라우트.

### 등록부 가드

- id가 겹치지 않는다. 고정 탭에 오늘·캘린더·입력·설정이 모두 있다.
- **배포한 id가 사라지거나 바뀌지 않는다.** 가드에 배포한 id 목록을 적고, 지우려면 이유를
  함께 적게 한다. id가 바뀌면 그 기능을 켜 둔 사용자의 설정이 조용히 꺼진다.

### 위젯

- `기능 관리`: 스위치를 켜고 꺼도 항목이 제자리에 머문다 / 탭 6개면 꺼진 탭형 스위치가
  비활성 / 고정 탭 자물쇠, 설정 행 드래그 불가 / 순서 변경이 저장된다.
- 탭형 경로는 테스트용 기능을 `moduleCatalogProvider` override로 주입해 검증한다.
- 오늘 탭: 버스 미설치면 카드 없음, 설치하면 카드 있음.
- 설정 탭: 버스 설치 시에만 `버스 도착` 행.
- 320·390·430pt에서 `기능 관리` 화면과 **6탭 탭바**가 넘치지 않는다(6탭에서 `캘린더` 라벨).

### 런타임

- iOS 시뮬레이터: 드래그 순서 변경, 스위치 켜기·끄기, **버스를 켜 둔 이전 빌드에서
  업그레이드했을 때 버스가 그대로 켜져 있는지**(이전 로직의 실전 검증, 반드시 밟는다).
- 기존 E2E 19건 통과. 기본 상태가 지금의 4탭과 같으므로 통과해야 한다.
- Android 에뮬레이터: 변경이 Dart뿐이라 필수는 아니나, 드래그 제스처 확인을 위해 배포 전 1회.

## 계획 단계에서 바뀐 것 (2026-10-02)

구현 계획을 쓰며 코드를 읽은 뒤 아래 네 가지를 스펙과 다르게 정했고, 사용자가 승인했다.
이 절이 위 본문보다 우선한다.

1. **버스 상세 설정의 마스터 스위치를 없애지 않고 등록부에 다시 묶는다.** 스위치가
   `installedModulesProvider`를 읽고 쓰므로 진실 공급원은 여전히 하나다. 기존 테스트가 거의 그대로
   살아남고, 이미 버스를 쓰는 사용자가 익숙한 자리에서 끌 수 있다.
2. **설정 탭의 `버스 도착` 행은 꺼져 있어도 보인다.** 스위치를 상세 화면에 남기면, 거기서 끄고
   뒤로 가는 순간 행이 사라져 "어디 갔지?"가 된다. "기능별 설정은 켜져 있을 때만 보인다"는
   규칙은 앞으로 만들 기능부터 적용한다.
3. **저장값에서 빠진 고정 탭은 카탈로그 순서로 설정 앞에 붙인다**("기본 순서 자리"가 아니다).
   고정 탭이 빠지는 경우는 첫 실행과 손상뿐이다. 첫 실행이면 결과가 기본 순서와 같고, 손상이면
   어느 자리든 정답이 없다.
4. **`BusCardHost` 안의 켜짐 검사를 없앤다. 설치 여부는 `InstalledTodayCards`만 본다.** 호스트
   안에서 비동기 provider를 하나 더 기다리면 `listenManual` 촉발 순서에 경합이 생긴다. "꺼져 있고
   정류장이 남아도 요청 0" 가드는 `InstalledTodayCards`를 띄우는 형태로 다시 겨눈다.

위 "위젯" 절의 `설정 탭: 버스 설치 시에만 버스 도착 행`은 2번에 따라 적용하지 않는다.
