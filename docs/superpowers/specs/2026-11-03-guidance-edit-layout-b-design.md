# 지도 기록 편집 화면 — B안 정리표 배치 (설계)

2026-11-03. 사용자와 대화로 정했다. 시안: Claude 디자인 캔버스 https://claude.ai/artifact/WvPs148zxodiyWZydh4hVa
의 **B안 · 정리표**(사용자 선택 — "먼저 적어야 하는 부분이 정리가 잘 되어 있다").

## 왜

지금 편집 화면(새 기록·기록 수정)은 첫 화면을 **분류 칸**(구분·범위 안내·진행 상태·사건 시각 정밀도·날짜·시각·기록 시각)이
다 차지하고, 현장에서 먼저 쓰는 제목은 화면 아래 끝, 녹음·사진·경과는 스크롤 아래에 있다. 칸마다 라벨 줄과 여백이 따로 있어
세로로 길다(사용자: "길게 차지해서 불필요한 공간이 많다").

쓰는 순간은 둘이다(사용자 설명).
- **현장**(상담 중·직후, 서서 휴대폰): 녹음, 증거 사진, 제목과 있었던 사실 간단히.
- **나중**(교무실): 검토한 것 확인, 판단 적기·보강. 녹음을 가져와 글로 보고 옮겨 적고, 경과 정리.

## 목표

- 제목이 맨 위. 그 아래 **정리표 카드** 한 장에 구분·상태·언제·어디서·누가를 한 줄씩.
- 녹음·사진·파일 버튼이 첫 화면 안에 보인다.
- 경과는 카드 하나. 들은 말·판단·조치는 **누를 때 펼쳐지는** 칸(둘 다 남긴다 — 사용자 결정).
- 긴 안내문 둘(범위 안내 `scopeNote`, 관련인 안내 `participantsHint`)은 화면에서 빼고 **ⓘ 버튼**으로 필요할 때만(사용자 결정).

## 목표가 아닌 것

- 저장값·판(추가만)·잠금·첨부 저장·녹음 흐름(`RecordingScreen`, `?record=1`)·기록 보기·목록은 바꾸지 않는다. **배치만** 바꾼다.
- 카메라로 바로 찍는 기능은 이번 범위가 아니다(지금 `사진`은 사진 보관함에서 고르기). → 아래 "열어 둔 것".
- 들은 말·판단·조치의 저장 구조, 관련인 칩 동작(쉼표·엔터·추천·잠금 시 추천 끔)은 그대로.

## 실패로 치는 것

- 320pt 폭에서 넘침(지금 가드가 있다).
- 이미 내용이 있는 들은 말·판단·조치가 접혀 있어 **안 보이는 것**(저장된 기록을 고칠 때 내용을 못 보고 지나친다).
- 안내문을 ⓘ로 옮기면서 그 내용이 아예 사라지는 것.
- 같은 `GuidanceContent`인데 배치 변경만으로 dirty가 되거나 판이 생기는 것.

## 화면 (위에서 아래)

AppBar는 그대로(취소 · `새 기록`/`기록 수정` · 저장).

1. **제목** — 라벨 줄 없이 큰 입력칸(시안: 20pt 굵게, 아래 골드 밑줄). 스크린리더 이름은 `제목`(지금처럼 `Semantics`). 비어 있으면 저장 시 `titleRequired` 그대로.
2. **정리표 카드**(흰 바탕·테두리·둥근 모서리, 행 사이 얇은 구분선). 각 행 = 왼쪽 칸 이름(고정 폭, 14pt `fieldLabel`) + 오른쪽 값.
   - `구분` — 생활지도 / 교육활동 침해. 행 끝에 **ⓘ**(→ `scopeNote`).
   - `상태` — 진행 중 / 마무리 / 이관.
   - `언제` — 사건 시각 요약(`formatOccurred` 결과) + 오른쪽 정밀도 표시(`정확히 ›` 등). 행을 누르면 **시트**가 열리고 그 안에 지금의 `OccurredInput`(정밀도 세그먼트 + 날짜/시각 칸 또는 대략 글)을 그대로 쓴다. 시트 아래에 `기록 시각 · …`(`createdOnSave` 또는 `formatStamp`) 한 줄.
   - `어디서` — 장소 입력(테두리 없는 한 줄 입력).
   - `누가` — `ParticipantChipsField`. 행 끝에 **ⓘ**(→ `participantsHint`). 칩이 늘면 행 높이가 자란다.
3. **첨부 버튼 한 줄** — `녹음`(채움, 빨간 점) · `사진` · `녹음 파일`. 기능은 지금 세 버튼(`recordKey`·`importImageKey`·`importAudioKey`) 그대로, 글자만 짧게. 그 아래 붙지 못한 녹음 경고(있을 때) → 첨부 목록(`AttachmentTile`) → `importHintSchoolPhone` 한 줄(지금 위치 규칙 유지).
4. **경과** — 카드형 입력, 칸 이름 `경과`, 최소 높이는 지금(5줄)보다 낮춰도 된다(구현자 판단, 3~4줄).
5. **들은 말 · 판단·조치** — 비어 있으면 점선 테두리 버튼 두 개가 한 줄에(`+ 들은 말` `+ 판단·조치`). 누르면 그 자리에 입력칸이 펼쳐지고 포커스가 간다. **내용이 있으면 처음부터 펼쳐져 있다.** 펼친 칸의 안내(`quotesHint`/`actionsHint`)는 입력칸 안 `hintText`로 넣는다(별도 줄 없음). 펼친 칸을 비워도 다시 접지는 않는다(구현자 판단으로 접어도 된다 — 단 내용이 있으면 접지 않는다).

**ⓘ 동작**: 누르면 작은 시트 또는 대화상자에 해당 문장을 보여 준다. 대화상자·시트는 `useRootNavigator: false`(잠금 덮개 규칙, 가드 있음 — 시트도 같은 규칙을 따른다). 버튼은 이름 있는 `IconButton`(`Icon(semanticLabel: …)`, tooltip 금지 가드).

## 지켜야 할 것 (가드)

- 키 13개(`GuidanceEditScreen.saveKey`…`statusKey`)와 `OccurredInput`·`ParticipantChipsField`의 키를 유지한다. 새 키: ⓘ 둘, `언제` 행, `+ 들은 말`·`+ 판단·조치` 버튼.
- `SegmentedButton`을 쓰면 `showSelectedIcon: false`(가드). 구분·상태 선택을 칩으로 바꾸면 선택 칩 규칙(테두리형 `PillChip`, CLAUDE.md 디자인 통일)을 따른다 — 둘 중 구현자 판단, 단 `kindKey(k)`·`statusKey(s)`로 누를 수 있어야 한다.
- `TextField`는 이름 규칙(`labelText`/`hintText`/`Semantics`, 가드), `InkWell`/`GestureDetector`는 `ButtonSemantics`(가드).
- `PickerFieldTile`로 날짜·시각(가드, `occurred_input.dart`는 그대로 시트 안에서 쓴다).

## 바뀌는 테스트 기대값 (지우지 않고 고친다)

`test/features/guidance/presentation/guidance_edit_screen_test.dart`
- `구분 바로 아래에 범위 안내가 보인다` → 범위 안내는 화면에 없고 **구분 행의 ⓘ를 누르면** 보인다.
- `관련인·들은 말·판단·조치 안내 문구가 보인다` → `participantsHint`는 누가 행 ⓘ에서, `quotesHint`·`actionsHint`는 칸을 펼쳤을 때 입력칸 안내로, `createdOnSave`는 언제 시트에서 보인다.
- `입력칸 이름은 … 14pt` → 정리표 행 이름이 14pt.
- 그 밖에 순서·라벨에 기대는 단정은 새 배치에 맞춘다. 선언 수는 줄이지 않는다(훅).

새 테스트(최소): 320/390pt 넘침 없음 · 제목이 정리표보다 위, 첨부 버튼이 경과보다 위 · 빈 들은 말은 접힘·누르면 펼침+포커스 · 내용 있는 기록은 펼쳐져 있음 · ⓘ 둘이 각 문장을 보여 줌 · 언제 행 → 시트에서 정밀도·날짜 변경이 저장값에 반영 · 배치만으로 dirty가 되지 않음.

## 구현자 판단으로 정한 것 (검토 반영, 내 판단)

1. **언제 시트는 즉시 반영이다.** 지금 화면의 세그먼트·날짜 칸이 누르는 즉시 상태를 바꾸므로 같은 동작을 유지한다. 시트 내용은
   부모 상태를 콜백으로 바꾸고 자기도 다시 그린다(`StatefulBuilder` 또는 시트 전용 위젯이 값을 들고 매 변경마다 부모에 올림).
   끌어서 닫거나 뒤로 가도 바꾼 값은 남는다(취소 개념 없음 — 지금과 같다). 대략 글은 입력할 때마다 부모로 올린다.
2. **언제 행 요약**은 `_current()`(정규화된 임시 `GuidanceContent`)로 `formatOccurred`를 부른 값. 오른쪽 표시는 `precision.label` + `›`.
   대략인데 글이 비면 `occurredUnknown`.
3. **구분·상태는 테두리형 `PillChip`**, 값 영역은 `Wrap`(320pt에서 한 줄에 안 들어가면 줄바꿈 허용 — 넘침보다 낫다). ⓘ는 행 끝 고정.
   `kindKey(k)`·`statusKey(s)`를 칩에 준다.
4. **들은 말·판단·조치 펼침**은 `_load()`가 끝난 시점에 정한다(내용이 있으면 펼침). 한 번 펼친 칸은 비워도 접지 않는다.
5. **버튼 글자는 새 상수**(`recordShort='녹음'`, `importImageShort='사진'`, `importAudioShort='녹음 파일'`)를 더하고 기존 상수는 바꾸지 않는다.

검토가 확인한 것: `경과`는 새 칸이 아니라 기존 `facts`(`labelFacts`)의 모양만 바뀐다. 기존 테스트 중 정밀도·날짜 키를 화면에서 바로 누르는
것(예: `guidance_edit_screen_test.dart` 154·206·208행 부근)은 **언제 시트를 먼저 여는 단계**를 더해 고친다.

## 열어 둔 것

- **카메라로 바로 찍기**: 사용자가 현장 흐름에 "증거 사진 찍고"를 말했다. 지금은 보관함에서 고르기뿐이라 촬영 버튼은 새 기능(권한 문구 `NSCameraUsageDescription`, 원본 그대로 SHA-256 규칙과의 관계)이다. 이번 배치 변경과 분리해 따로 정한다.

## 확인 방법

위젯 테스트 + 전체 `flutter test`·`analyze`, 시뮬레이터(verify 스킬)에서 새 기록·기록 수정 두 화면을 320/402pt 캡처로 시안과 비교, `녹음으로 새 기록` 흐름이 그대로 도는지.
