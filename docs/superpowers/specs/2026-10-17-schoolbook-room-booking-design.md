# 장소 예약(스쿨북) 탭 — 설계

날짜: 2026-10-17 · 선행: `2026-10-02-feature-modules-design.md`(기능 모듈), `2026-10-03-module-settings-design.md`(기능별 설정)
시안: https://claude.ai/artifact/672PhkcEvjmfUK53EK1ZMV — 사용자 선택 **B**(교실 한 줄 + ◀ 날짜 ▶ + 여러 교시 한 번에 예약)

## 배경과 목표

[스쿨북](https://schoolbook.zzolab.com)(저장소 `Szzng/SchoolBook`)은 학교별 특별실·교구 예약 서비스다.
455개 학교가 쓰는데 **사실상 컴퓨터 앞에서만 확인한다**(사용자). 체육 수업을 앞두고 "체육관이 그 시간에 비었나"를
휴대폰에서 바로 보고, 비어 있으면 그 자리에서 잡고 싶다는 것이 출발점이다.

- 공직플랜 안에서 **장소(교실) 하나를 골라 하루 예약 현황**을 본다.
- 비어 있으면 **예약**하고, 잘못 잡았으면 **취소**한다.
- 컴퓨터에서 하기 좋은 일(설정·관리)은 계속 스쿨북 웹에서 한다.
- 스쿨북 제작자에게 허락을 받았다(사용자). **1단계는 스쿨북에 PR 없이** 지금 있는 API만 쓴다.

## 결정 (사용자 선택, 2026-10-17)

| 질문 | 결정 |
|---|---|
| 보는 단위 | **교실 하나 × 하루**. 그날 모든 교실을 한꺼번에 보지 않는다 — "체육 수업이면 체육관만 보면 된다. 다 나오면 또 찾아야 한다" |
| 날짜 | **하루씩** 넘긴다. 한 달 달력은 만들지 않는다 |
| 화면 | ~~시안 B~~ → **시안 A**(2026-10-17 실기기 피드백으로 변경) — 교실 칩 한 줄 · 이번 주 월~금 날짜 띠(◀ ▶ 주 넘기기) · 교시 줄 끝 버튼 하나([예약] 또는 내 예약의 [취소]). 저장값이 있으면 [예약]이 바로 보낸다. 시안 2차: https://claude.ai/artifact/LDaf9PwNQzF8qwsCYj1Sut |

| 취소 | **한다** |

| 비밀번호 | **예약용 비밀번호를 미리 받아 두고 예약할 때 자동으로 채운다**(사용자 변경 2026-10-17 — 처음엔 매번 입력이었다). **취소할 때는 다시 묻는다** — "내가 예약한 교실을 취소하려면 나한테 다시 요청하면 될 것 같아" |

| 정원 | 교실마다 정원이 있어 **한 교시에 여러 반**이 들어갈 수 있다. 예약자를 모두 보이고 남은 자리를 함께 적는다 |

| 테스트 학교 | 운영 서버에 **테스트 학교 `플랜테스트`를 가입시켰다**(사용자 요청, 2026-10-17) |

## 목표 아닌 것 / 실패로 보는 것

- 아님: 물품 예약 · 한 달 달력 · 교실 여러 개 한눈에 · 교시·교실·고정 시간표·공지 편집 · 공지 쓰기 ·
  캘린더/오늘 탭/알림 연동 · 여러 학교 동시 등록 · 오프라인 예약.
- **실패**: 비밀번호를 일반 설정 파일·로그·스낵바에 남기는 것(보안 저장소에만 둔다) · 예약이 됐는지 안 됐는지 화면이 모호한 것(조용한 실패) ·
  스쿨북 서버를 화면 진입마다 과하게 두드리는 것(운영 서버는 `15/s` 제한, 455개 학교가 쓰는 실서비스다) ·
  공직플랜 다른 기능에 스쿨북 데이터가 새어 들어가는 것.

## 스쿨북 API (쓰는 것만)

계약 원문은 SchoolBook 저장소 `BackEnd/docs/api.md`. 주소 `https://schoolbook.zzolab.com/api/`.

- **인증은 헤더 `Authorization: <학교 코드 13자>` 하나다.** 학교 코드가 있으면 그 학교의 설정까지 바꿀 수 있는
  권한이므로 **앱은 아래 GET 셋 + 예약 POST + 예약 DELETE만 부른다.**
- `GET /api/accounts/login/<code>/` (헤더 없음) — 학교 이름 · 교시 · 게시 중 공지. 없는 코드 → `401`.
  교시가 `[]`이면 아직 스쿨북 설정을 안 한 학교다.
- `GET /api/rooms/` — 교실 목록 `[{id, name, capacity}]`, 이름순.
- `GET /api/rooms/<room_id>/bookings/?date=YYYY-MM-DD` — 하루. 교시마다 `remaining` · `fixed[{booker}]` ·
  `bookings[{id, booker, cancel_reason, canceled_at}]` · `archived`. 지난 날짜도 조회된다.
- `POST /api/rooms/<room_id>/bookings/` — `{date, period_ids[], booker, password}`. **하나라도 자리가 없으면 아무것도
  안 생긴다**(`400`, `detail`을 그대로 보여 준다).
- `DELETE /api/rooms/<room_id>/bookings/<booking_id>/` — `{password}`. 틀리면 `400`.

규칙(서버가 검사한다 — 앱은 미리 막되 서버 판단을 믿는다):
- 예약 가능한 날: **오늘 ~ 다음 해 2월 말일의 평일**(`booking_window.py`의 `is_bookable_date`).
- 예약자 1~20자, 비밀번호 숫자 4자리.
- 지난 날짜 예약과 고정 시간표 예약은 취소할 수 없다.
- 상태 코드: `400` 입력 문제(`detail`을 보여 준다) · `401` 코드 틀림 · `403` 교시 미등록 · `404` 없는 대상(영어 문구라 보여 주지 않는다).

## 화면

> ⚠️ 아래 화면 절은 처음 정한 **시안 B** 기준이다. 지금 화면은 시안 A다 — 위 결정 표와 CLAUDE.md `### 장소 예약` 절이 기준이다.

### 장소 예약 탭 (시안 B)

```
            SCHOOLBOOK
            장소 예약                 ⚙
┌───────────────────────────────┐
│ 체육관               바꾸기 ▾ │
└───────────────────────────────┘
   ◀      10월 20일 (화)      ▶
 1교시 09:00   고정 · 3-2
 2교시 09:50   ☑ 비어 있음
 3교시 10:40   5-1, 6-2 · 1자리 남음   ☐
 4교시 11:30   ☑ 비어 있음
 5교시 13:20   6-3
 6교시 14:10   ☐ 비어 있음
   [ 2·4교시 예약하기 ]
```

- **교실 줄**: 누르면 교실 목록 시트(이름 + 정원). 고르면 그 교실의 같은 날짜를 다시 부른다.
  **마지막으로 본 교실을 기억**해 다음에 열면 바로 그 교실이 뜬다. 기억한 교실이 지워졌으면 목록 첫 교실.
- **날짜 줄**: ◀ ▶로 **평일만** 하루씩 넘긴다(토·일을 건너뛴다). 처음 열면 오늘, 주말이면 다음 월요일.
  ▶는 예약 가능한 마지막 날에서 멈춘다. ◀는 지난 날도 보여 준다(조회만 — 체크·취소 없음).
- **교시 줄 하나**: 교시 이름 · 시각(있으면) · 그 칸의 사람들(고정 + 날짜 예약, 쉼표로) · 남은 자리.
  - 남은 자리가 0이면 체크할 수 없다.
  - 정원 1인 교실은 `1자리 남음`을 적지 않고 시안처럼 `비어 있음`/예약자만 보인다.
  - 고정 시간표 예약은 `고정 · 3-2`처럼 구분한다. **취소된 예약(`cancel_reason`이 있음)은 보이지 않는다**
    — 빈자리 계산에서도 빠지는 행이라, 보여 주면 "누가 있는데 비었다"로 읽힌다.
  - `archived` 교시(지운 교시)는 그날 예약이 걸려 있을 때만 서버가 준다 — 체크할 수 없게 흐리게 보인다.
- **예약 버튼**: 하나 이상 체크하면 아래에 `2·4교시 예약하기`가 뜬다. 없으면 숨는다.
- **⚙**: 기능 상세 설정(학교 링크 바꾸기)으로 가는 지름길(설정 규칙 — 탭형 기능은 자기 탭에 ⚙ 하나를 둘 수 있다).
- 화면 위 공지 배너는 **만들지 않는다**(이번 범위 밖). 로그인 응답에 공지가 오지만 쓰지 않는다.

### 예약 시트

1. `n교시 예약하기`를 누르면 아래에서 작은 시트가 올라온다 — 제목 `체육관 · 10월 20일(화) 2·4교시`.
2. 예약자 칸에 **기억한 이름**, 비밀번호 칸(숫자 4자리, 가림)에 **저장한 비밀번호가 미리 들어가 있다** — 둘 다 있으면 `예약`만 누르면 된다.
   저장한 비밀번호가 없으면 비밀번호 칸에 포커스가 있다.
3. `예약`을 누르면 POST. 성공하면 시트가 닫히고 목록을 다시 부르고 스낵바 `2·4교시를 예약했어요`.
   예약자 이름과 비밀번호를 저장값으로 갱신한다(성공했을 때만 — 처음 예약하면서 넣은 비밀번호가 다음부터 채워진다).
4. 실패하면 **시트가 남고** 시트 안에 서버의 `detail`을 보인다(예: `2교시의 남은 자리가 없습니다.`). 그사이 남이 먼저
   잡은 경우라 목록도 다시 부른다.
- 확인 창 없음. 버튼은 요청 중에 다시 눌리지 않는다(두 번 예약 방지).

### 취소 시트

- 날짜 예약 이름을 누르면 시트 — 제목 `5-1 · 3교시 예약 취소`, 비밀번호 칸 하나(**비어 있다** — 저장한 비밀번호를 채우지 않는다), `예약 취소` 버튼.
- 성공 → 닫힘 + 목록 다시 부르기 + 스낵바 `예약을 취소했어요`. 비밀번호가 틀리면 시트 안에 `detail`.
- **오늘 이전 날짜의 예약과 고정 예약은 눌러도 시트가 뜨지 않는다.** 한 칸에 예약이 여럿이면 이름마다 누를 수 있어야 한다.
- 누구의 예약이든 시트가 뜬다 — 비밀번호를 아는 사람만 지울 수 있다는 스쿨북 규칙을 그대로 따른다.

### 처음 쓰기 · 학교 연결

- 기능을 켜고 처음 들어오면 빈 상태: `스쿨북 학교 링크를 붙여 넣어 주세요` / `스쿨북에서 쓰는 학교 주소를 복사해 오면 됩니다`
  + 입력칸 + `연결`.
- 입력은 **전체 링크와 코드 13자 둘 다** 받는다. 링크는 `https://schoolbook.zzolab.com/<code>` 또는
  `…/<code>/room/<id>`처럼 뒤에 경로가 붙어 있을 수 있다 → **첫 경로 조각**이 코드다(순수 함수로 뽑는다).
- `연결`은 login API로 검증한다. 성공하면 학교 이름을 보여 주며 저장하고 탭으로. `401`이면 `학교를 찾을 수 없어요. 링크를 확인해 주세요`.
- 상세 설정(`기능 관리 › 장소 예약 › 상세 설정`): 연결된 학교 이름 · `학교 링크 바꾸기` · `연결 끊기`(저장값 삭제).
  예약자 이름과 **예약 비밀번호**(숫자 4자리, 가림 — 저장 · 지우기)도 여기서 고친다. `연결 끊기`는 비밀번호도 지운다.

### 오류 · 빈 상태

| 상황 | 화면 |
|---|---|
| 네트워크 실패 · 시간 초과 | 목록 자리에 `불러오지 못했어요` + `다시 시도` |
| `401`(학교 코드가 바뀌었거나 학교가 지워짐) | `학교 연결이 끊겼어요` + `다시 연결` |
| `403` / 교시 0개 | `스쿨북에서 교시를 먼저 등록해 주세요` (컴퓨터에서 할 일이다) |
| 교실 0개 | `스쿨북에 등록된 장소가 없어요` |
| 조회(GET)·예약(POST)의 `404`(보던 교실이 지워짐) | 교실 목록을 다시 불러 첫 교실로 |
| 취소(DELETE)의 `404`(남이 먼저 지운 예약) | 시트 안에 `이미 취소된 예약이에요` + 목록 다시 부르기. **교실은 그대로** (설계자 판단) |
| 예약·취소 요청의 네트워크 실패·시간 초과 | 서버에는 이미 반영됐을 수 있다(스쿨북 API에 중복 방지 키가 없다). **자동 재시도하지 않는다.** 시트를 닫고 목록을 다시 불러 스낵바 `결과를 확인하지 못했어요. 목록을 확인해 주세요` — 사용자는 다시 불러온 목록에서 실제 결과를 본다 (설계자 판단) |
| 그날 교시 목록이 비었음 | `이날은 예약할 수 있는 교시가 없어요` |

## 저장

- **DB를 쓰지 않는다.** 예약 데이터는 스쿨북 서버에 있고 앱은 매번 불러 본다(메모리 캐시도 두지 않는다 — 남이 방금 잡은 자리를 보여 줘야 한다).
- `shared_preferences` 키 하나(`schoolbook_settings_v1`, JSON): `code` · `schoolName` · `lastRoomId` · `booker`.
  **비밀번호 칸은 없다**(가드 테스트로 막는다).
- **예약 비밀번호는 기기 보안 저장소**(`flutter_secure_storage` — iOS Keychain · Android Keystore 암호화)의 키 `schoolbook_password_v1`
  하나에 둔다(설계자 판단). 숫자 4자리는 다른 곳의 비밀번호와 겹치기 쉬워 일반 설정 파일(prefs · 기기 백업에 평문으로 실린다)에 두지 않는다.
- 학교 코드를 Keychain이 아니라 prefs에 둔 것은 **설계자 판단**이다 — 학교 코드는 원래 교사들이 메신저로 주고받는 링크의
  일부이고, 휴대폰 잠금이 풀린 사람은 웹 브라우저로도 같은 일을 할 수 있어 Keychain이 더 막아 주는 것이 없다. 새 패키지도 들지 않는다.
- 저장 키 이름과 기능 id는 **저장값이라 배포 뒤 바꾸지 않는다**(리포 규칙).

## 기능 등록

- 등록부(`module_catalog.dart`)에 **탭형 선택 기능** 하나: id `schoolbook`(저장값), 이름 `장소 예약`, 기본 꺼짐,
  `settingsRoute`로 상세 설정. 라우트는 설치와 무관하게 항상 등록한다(`module_catalog_test.dart`).
- 코드는 `lib/features/schoolbook/` — `data/`(API 클라이언트 · 응답 파서 · 설정 저장소) · `domain/`(Freezed 모델 ·
  날짜 넘기기 · 링크 파싱 · 교시 줄 판정 같은 순수 함수) · `presentation/`. 버스 기능(`features/bus/`)의 직접 호출 패턴을 따른다.
- 문자열은 `SchoolbookStrings`(`core/constants/strings/`), 색은 기존 `AppColors` 토큰만(고정=`info` 계열, 예약됨/빈자리는
  기존 의미 색에서 고른다 — 새 토큰이 필요하면 추가만 하고 기존 값은 바꾸지 않는다).
- **격리**: 캘린더·오늘·알림·내보내기·휴지통·단축어는 `schoolbook`을 모른다(지도 기록의 `guidance_isolation_test`와 같은 가드).
  `전체 데이터 초기화`는 이 기능의 설정(학교 연결·예약자)을 남긴다 — 앱 안에 이 기능의 데이터가 없다.

## 외부 의무

- **개인정보처리방침을 고쳐야 한다.** 지금 문서는 "자체 서버 없음"과 공공데이터 호출만 적고 있다. 이 기능은 사용자가
  켰을 때 **학교 코드 · 예약자 이름 · 비밀번호를 스쿨북 서버(제3자 운영)로 보낸다** — 그 사실과 운영 주체, 기기에 남는 것
  (코드·학교 이름·예약자 이름 · 보안 저장소의 예약 비밀번호)을 §2·§5·§6에 더한다.
- 스토어 개인정보 라벨(`수집 안 함`)이 그대로 맞는지는 **제출 때 재확인**한다 — 개발자가 받는 것은 없지만 제3자 서비스로 데이터가 간다.
- **Android에도 나가므로 Play Console `데이터 보안` 양식**(제3자에게 데이터 전송 여부)도 같은 때 고친다. `/store-listing` 점검 범위에 넣는다.
- 스쿨북 제작자에게 받은 허락의 범위(외부 앱이 예약 API를 부르는 것, 앱 이름에 `스쿨북`을 쓰는 것)를 문서로 남겨 둔다.
- ATS 예외는 필요 없다(https).

## 테스트

- 순수 함수: 링크 → 코드(전체 링크 · 뒤 경로 · 코드만 · 잘못된 입력) · 평일 넘기기(금→월, 주말 시작, 마지막 예약 가능일에서 멈춤,
  2월 말 윤년) · 교시 줄 판정(체크 가능 / 취소 가능 / 취소된 예약 숨김 / 정원 1 표기).
- 파서: **실측 응답을 픽스처로 저장해** 쓴다(버스 기능에서 손으로 쓴 픽스처가 현실과 어긋났던 교훈). 예약 · 취소 오류 응답 포함.
- 위젯: 가짜 클라이언트로 B 화면 — 체크 → 버튼 문구 · 예약 성공/실패(시트 유지 + `detail`) · 취소 · 오류 상태 표 전부 ·
  **320·390·430pt 넘침**(긴 교실 이름 · 한 칸에 예약자 여럿).
- 가드: 저장 JSON에 비밀번호가 없다 · 비밀번호를 읽고 쓰는 곳은 보안 저장소 파일 하나 · 취소 시트는 저장한 비밀번호를 채우지 않는다 · 앱이 설정 변경 API(PUT/PATCH, rooms POST 등)를 부르지 않는다 · 격리.
- 시뮬레이터·에뮬레이터: 실제 스쿨북 서버로 끝까지(연결 → 조회 → 예약 → 취소). **테스트 학교 `플랜테스트`만 쓴다** — 실제 학교 예약을 건드리지 않는다.
  - 이 학교의 코드는 **리포에 적지 않는다.** 리포가 공개이고 학교 코드가 곧 그 학교의 쓰기 권한이다. 실측 픽스처를 저장할 때 코드가 들어간 칸은 가린다.
  - 픽스처를 뜨려면 테스트 학교에 교시 · 정원 1 교실 · 정원 2 이상 교실 · 고정 시간표 · 설정 변경으로 취소된 예약(409 흐름)을 먼저 만들어 둔다(스쿨북 웹이나 API로, 이 테스트 학교에서만).
- iOS와 Android 양쪽에서 위 흐름을 확인한다.
