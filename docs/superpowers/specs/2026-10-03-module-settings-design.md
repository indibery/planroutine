# 기능별 설정은 기능 관리 안으로 — 설계

날짜: 2026-10-03 · 선행: `2026-10-02-feature-modules-design.md`(기능 모듈)

## 배경

TestFlight 1.4.0(v162)을 써 본 사용자의 지적이다(2026-10-03):

> 설정에 버스도착 메뉴가 기능관리에 들어가 있지 않고 따로 나오거나 중복된 느낌이야.
> 기능관리에서 켜야 설정에서 보여야 할 것 같고 기능 관리 안에서 켜면 그 안에서
> 한번더 자세한 버스관련 기능을 설정할 수 있으면 좋겠어. 앞으로 기능 추가 할 수 있는
> 것들이 늘어 날테니 관련해서 복잡하지 않은 설정메뉴 관리를 생각해 봐야 할 것 같아.

지금은 버스를 켜고 끄는 스위치가 **두 곳**(기능 관리 행, 버스 상세 화면)에 있고, 설정 탭의
`버스 도착` 행은 **꺼져 있어도 항상** 보인다. 기능 모듈 계획 단계에서 승인한 이탈 ①·②가
만든 상태다. ②의 근거("상세 화면에서 끄고 나가면 행이 사라져 당황한다")는 상세 화면에도
스위치가 있다는 ①에 기대고 있었다.

## 목표

- 기능이 늘어나도 **설정 탭의 길이와 구조가 변하지 않는다.**
- 한 기능의 켜기·끄기와 상세 설정이 **한 자리**(기능 관리 안 그 기능의 행)에 모인다.

## 결정 (사용자 선택, 2026-10-03)

| 질문 | 결정 |
|---|---|
| 켠 기능의 상세 설정으로 들어가는 길 | **기능 관리 한 곳만.** 설정 탭에는 기능별 행을 두지 않는다 |
| 상세 화면의 켜기 스위치 | **없앤다.** 켜고 끄는 곳은 기능 관리 행 하나 |
| 설정이 필요한 기능을 처음 켰을 때 | **켜기만 하고 행 부제로 안내한다.** 상세로 자동 이동하지 않는다 |

## 설정 메뉴 규칙 (앞으로의 모든 기능에 적용)

1. **설정 탭에는 앱 공통 설정만 둔다** — 화면 테마·기능 관리·도장·내보내기·캘린더 연동·
   알림·휴지통·데이터 관리·개인정보처리방침·앱 정보. 선택 기능의 설정 행은 만들지 않는다.
2. **기능별 설정은 `기능 관리` › 그 기능의 행 › 상세 화면**으로 들어간다. **켜져 있을
   때만** 들어갈 수 있다(꺼져 있으면 `›`가 없고 행을 눌러도 이동하지 않는다).
3. **켜고 끄는 스위치는 기능 관리 행에 하나뿐이다.** 상세 화면에는 켜짐 스위치를 두지 않는다.
4. 상세 설정이 없는 기능은 `settingsRoute`가 없고 `›`도 없다.
5. 처음 켰는데 설정이 비어 있으면 **화면을 옮기지 않고 행 부제로 다음 행동을 알린다.**

## 화면

```
── 설정 탭 ──                       ── 기능 관리 › 기능 ──
[화면 테마]                         꺼짐
[기능 관리     1개 사용 중 ›]       [🚌 출퇴근 버스                 [○]]
[도장 모양]                              오늘 카드 · 오늘 탭 맨 위에 버스 도착 시간을 보여줘요
[CSV 내보내기]                      켜짐 · 정류장 없음
[알림] …                            [🚌 출퇴근 버스             [●]  ›]
   ↑ `버스 도착` 행이 없다               정류장을 등록해 주세요
                                    켜짐 · 정류장 있음
                                    [🚌 출퇴근 버스             [●]  ›]
                                         정류장 2곳

── 출퇴근 버스 (상세) ──
오늘 탭 맨 위에 출퇴근 버스 도착시간을 보여줍니다   ← 기능 소개 한 줄(그대로)
[출발 정류장 …  ›]
[도착 정류장 …  ›]
[출근·퇴근 시간대]
[카드 모양  간단히 | 시간 축]
```

- 켜진 행: **행을 누르면 상세로, 스위치를 누르면 켜고 끈다.** 두 영역이 갈린다.
- 꺼진 행의 부제는 지금처럼 `자리 · 설명`이다. 켜진 행은 그 자리를 기능이 주는 요약이 대신한다.
- 탭이 가득 차 막힌 탭형 기능의 안내(`탭이 가득 찼어요`)는 그대로다.
- 상세 화면에 들어간 채 기능 관리로 돌아와도 행은 제자리다(목록은 등록부 순서).

## 구현 방식

### 등록부 항목 확장 (`AppModule`)

- `String? settingsRoute` — 상세 화면 경로. null이면 상세가 없다(`›` 없음).
- `Widget? settingsSummary` — 켜져 있을 때 행 부제로 그릴 위젯. null이면 `description`을 쓴다.
  **위젯으로 두는 이유:** 기능 관리 화면이 각 기능의 내부 상태(정류장 수 등)를 몰라도
  된다. 등록부가 이미 카드형 기능의 `card` 위젯(`BusCardHost`)을 들고 있는 것과 같은 방식이다.
- 버스 항목: `settingsRoute: AppRoutes.busSettings`, `settingsSummary: BusModuleSummary()`.

### 버스

- `BusModuleSummary`(신규, 작은 ConsumerWidget) — `busSettingsProvider`를 읽어 요약 문구를 그린다.
- `buildBusSettingsSummary`는 `installed` 인자와 `꺼짐` 갈래를 잃는다(켜져 있을 때만 쓰인다).
  문구: 정류장 0곳 → `정류장을 등록해 주세요`, N곳 → `정류장 N곳`.
  `summaryOff`·`summaryNoStop`·`summaryStops`는 새 문구로 바꾸거나 지운다(쓰는 곳이 남지 않게).
- `BusSettingsTiles`에서 `표시` 스위치를 없애고, 나머지 줄(정류장·시간대·모양)을 **항상**
  보인다. `showTitle`·`showSubtitleOn`·`showSubtitleOff` 문자열은 쓰는 곳이 없어지면 지운다.
- `BusSummaryListTile`을 설정 탭에서 뺀다. 파일은 쓰는 곳이 없어지면 지운다.
- `/bus/settings` 라우트와 `BusSettingsScreen`은 그대로다. push 주인 탭은 계속 설정이다
  (기능 관리도 설정 소속이다).

### 기능 관리 화면 (`ModulesScreen`)

- 선택 기능 행을 `SwitchListTile`에서 **스위치 + `›`를 가진 행**으로 바꾼다. 켜져 있고
  `settingsRoute`가 있을 때만 행 탭이 `context.push(settingsRoute)`를 한다.
- 키는 그대로 둔다: `switchKey(id)`는 스위치에, 행 전체에는 `rowKey(id)`를 새로 둔다.
- 스위치에 `activeThumbColor`를 주지 않는다(전역 `switchTheme` 색 가드).

## 테스트

- **기능 관리:** 꺼진 행에는 `›`가 없고 눌러도 이동하지 않는다 / 켜면 `›`와 요약이 생긴다 /
  켜진 행을 누르면 `settingsRoute`로 간다 / 스위치를 눌러도 이동하지 않는다 /
  `settingsRoute`가 없는 기능은 켜져도 `›`가 없다(테스트용 기능 주입).
- **버스 요약:** 0곳 → 안내 문구, 1·2곳 → 개수(순수 함수).
- **버스 상세:** 스위치가 없고 정류장·시간대·모양 줄이 늘 보인다. 기존
  `bus_settings_tiles_test.dart`의 스위치 테스트는 **지우지 않고** 같은 의도를 새 구조로
  다시 겨눈다(예: "꺼져 있으면 정류장 줄이 숨는다" → "상세에는 켜짐 스위치가 없고 줄이 늘 보인다").
  파일별 테스트 선언 수가 줄면 훅이 막는다.
- **가드(신규):** 설정 탭(`settings_screen.dart`)이 등록부의 선택 기능 `settingsRoute`로
  직접 들어가지 않는다 — 소스에서 그 경로 상수·기능 요약 위젯을 찾지 않는다. 설정 탭에 기능
  행이 다시 생기는 회귀를 막는다. 등록부 가드(`module_catalog_test.dart`)에 "`settingsRoute`가
  있으면 라우터에 등록돼 있다"를 더한다.
- **런타임:** 시뮬레이터(DeviceHub로 사람에게 보이게)에서 설정 탭에 버스 행이 없는지, 기능
  관리에서 켜고 `›`로 들어가 정류장을 바꾼 뒤 돌아왔을 때 요약이 바뀌는지.

## 바뀌는 이전 결정

- 기능 모듈 계획 이탈 **①(버스 상세 스위치를 남기고 등록부에 묶는다)을 뒤집는다** — 스위치를 없앤다.
- 이탈 **②(설정 탭의 버스 행은 꺼져도 보인다)를 뒤집는다** — 설정 탭에서 버스 행이 없어진다.
  "기능별 설정은 켜져 있을 때만 보인다"는 규칙을 버스부터 적용한다.
- `2026-10-02-feature-modules-design.md` 끝에 이 문서를 가리키는 한 줄을 붙이고, CLAUDE.md
  `### 기능 모듈 (등록부)`의 해당 bullet(상세 스위치·버스 행 예외)을 고친다.

## 건드리지 않는 것

- 공통 설정의 자리·순서(테마·도장·알림 등).
- 버스 상세 화면의 내용(정류장 검색·시간대·모양)과 저장 형식(`bus_settings_v1`).
- 기능 관리의 `내 탭` 섹션(순서 변경).
- 단축어(App Intents) 코드(보류 중).
