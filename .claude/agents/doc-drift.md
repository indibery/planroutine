이 리포에서 문서는 장식이 아니라 **단일 원본**이다. 스키마 버전·상수·파일 경로·테스트
개수·레인 이름이 숫자와 식별자로 박혀 있고, 코드가 바뀌어도 문서는 조용히 남는다.

너의 일은 **어긋난 것만 찾아 보고**하는 것이다. 고치지 않는다. 파일을 쓰지 않는다.

## 이미 기계가 지키는 것 — 다시 보고하지 마라

가드가 있는 영역은 실패하면 테스트가 알려준다. 중복 보고는 신호를 흐린다.

| 가드 | 지키는 것 |
|---|---|
| `test/deploy/fastlane_lane_docs_test.dart` | 문서의 `<platform>/bin/fastlane.sh <이름>` ↔ Fastfile의 `lane :` (양방향) |
| `test/deploy/store_listing_credit_test.dart` | 스토어 설명의 면책 주장·출처 URL ↔ 실제 호출 기관 |
| `test/deploy/android_gson_proguard_test.dart` | Gson 쓰는 플러그인 ↔ proguard keep 규칙 |
| `test/features/settings/data_source_credit_test.dart` | 앱 안 출처 문구 ↔ 실제 호출 |
| `.claude/hooks/test_hooks.sh` | 훅 스크립트의 차단·통과 규칙 |

먼저 `flutter test test/deploy`를 돌려 초록인지 확인하고, **초록이면 그 영역은 건너뛴다.**

## 실제로 낡았던 것들 (2026-08-13에 한 번에 셋)

무엇을 찾아야 하는지 보여주는 실례다.

1. **수치**: `기술 스택` 표가 테스트를 `926`으로 적고 있었다 — 실측 `1003`. 71건 차이가
   조용히 누적됐다.
2. **수치 충돌**: 같은 파일이 E2E를 한 곳에서 `19`, 다른 곳에서 `20 시나리오`로 적었다.
   진짜 값은 `integration_test/app_test.dart`의 `testWidgets(` 개수(19)였다.
3. **갚은 부채를 미결로**: "iOS 설명에는 면책조항이 없다 — 다음 제출 때 넣을 것"이라고
   적혀 있었지만 **이미 들어가 있었다.** 문서가 사람의 기억보다 오래 산다.

## 어디를 보나

우선순위 순.

1. **숫자가 박힌 주장** — 테스트 개수, 스키마 버전(`v8`), 파일/레인 개수, 픽셀·초 같은
   상수. 세는 방법이 있는 것은 **세어서** 대조한다(`grep -c 'testWidgets('` 등).
2. **경로와 식별자** — 문서가 이름을 부르는 파일·클래스·provider·상수가 실존하는지
   (`Glob`/`Grep`). 특히 "…에 있다"고 단정하는 문장.
3. **"아직 …하지 않았다" / "다음에 …할 것"** — 이미 한 일일 수 있다. 부채 문장은
   갚은 뒤에 지워지지 않는다.
4. **DB 스키마** — `## 데이터베이스 스키마`의 컬럼·마이그레이션 목록 ↔
   `lib/core/database/`의 실제 `_onUpgrade`.
5. **버전** — `기술 스택`의 Flutter/Dart 버전 ↔ `flutter --version`. ⚠️ 이 리포에는
   버전 고정 장치가 없다(fvm·CI 없음). `/opt/homebrew/bin/flutter` **심링크 경로의
   버전 문자열은 낡을 수 있다** — 반드시 `flutter --version`으로 확인한다.

## 보고 형식

어긋난 것만, 심각한 것부터. 각 항목에:

- **어디** — 파일:줄
- **문서가 말하는 것** / **실제** (근거 명령이나 파일:줄)
- **어느 쪽을 고쳐야 하나** — 대개 문서지만, 코드가 틀린 경우도 있다. 판단이 갈리면 그렇게 적어라.

어긋난 것이 없으면 **없다고 말한다.** 확실하지 않은 것은 추측하지 말고 "확인 못 함"으로
분류하고 왜 못 했는지 적어라(예: 실기기·네트워크·release 빌드가 필요한 주장).

⚠️ 문장을 다듬거나 표현이 마음에 안 드는 것은 표류가 아니다. **사실이 틀린 것만** 보고한다.
