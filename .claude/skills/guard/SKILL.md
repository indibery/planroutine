# 함정 → 가드 승격

이 리포의 규율은 **"재발한 함정은 문서에서 가드로 올린다"** 다. 문서는 읽는 사람이 있어야
작동하고, 가드는 읽지 않아도 작동한다.

## 먼저 판단: 가드로 올릴 것인가

| 신호 | 판정 |
|---|---|
| 같은 실수를 **두 번** 밟았다 | 올린다 |
| 같은 사실이 **두 곳**에 적힌다(코드 ↔ 문서/설정) | 올린다 — 한쪽만 고치는 것이 곧 재발이다 |
| 원인이 **구조적으로 사라졌다**(업스트림 수정, 코드 경로 제거) | 가드도 함께 지운다 |
| "이제 안 걸릴 것 같다" | **빼지 않는다** — 근거가 예감이다 |
| 재현에 네트워크·실기기·release 빌드가 필요하다 | 가드로 못 만든다 → 아래 "가드가 못 하는 것" |

## 이미 있는 셋 — 새 가드는 이걸 베낀다

복사하지 말고 **읽고 형태를 따른다**(복사하면 원본과 갈라진다).

| 가드 | 대조하는 두 곳 |
|---|---|
| `test/deploy/fastlane_lane_docs_test.dart` | Fastfile의 `lane :` ↔ CLAUDE.md·deploy SKILL.md의 `bin/fastlane.sh <이름>` |
| `test/features/settings/data_source_credit_test.dart` | `bus_api_client.dart`의 기관코드·호스트 ↔ 앱 내 출처 문구 |
| `test/deploy/android_gson_proguard_test.dart` | Gson을 쓰는 플러그인 소스 ↔ `proguard-rules.pro` keep 규칙 |
| `test/deploy/store_listing_credit_test.dart` | 실제 호출 기관 ↔ **두 스토어 설명**의 출처 절(문서끼리도 대조) |
| `.claude/hooks/test_hooks.sh` | 훅 스크립트 ↔ 실제 명령 문자열(오차단 케이스가 자산) |

공유 표는 따로 둔다 — `test/helpers/data_source_agencies.dart`를 위 두 가드가 함께 읽는다.
같은 낱말을 두 테스트에 각각 박으면 **세 번째 원본**이 생긴다.

## 규칙 넷

### 1. 양방향으로 검사한다

한 방향만 보면 절반이 조용히 썩는다.

- **없는 것을 적었다** → 실패 (문서가 존재하지 않는 레인을 명령으로 적어 세션이
  `Could not find lane`으로 헛돌았다, 2026-08-06)
- **있는 것을 안 적었다** → 실패 (소스를 추가하고 출처 표시를 잊는 순간이 정확히
  라이선스를 어기는 순간이다)

### 2. 면제는 **이유와 함께** 목록에 넣는다

`_internalLanes`·`_exempt` 같은 면제 목록은 필요하다. 다만 이유가 없는 항목을 늘려
통과시키면 **역방향 검사가 무력해진다.** 이유가 비어 있지 않은지까지 검사하는 테스트를
함께 둔다(`android_gson_proguard_test.dart`가 그렇게 한다).

### 3. 검사가 살아 있는지도 검사한다

대조 대상을 **하나도 못 찾았을 때 통과**하는 가드는 가드가 아니다. 경로를 오타 내거나
플러그인 배치가 바뀌면 조용히 0건을 훑고 초록불이 된다. "대상을 실제로 찾아냈다"를
별도 테스트로 고정한다.

### 4. 회귀를 심어 깨지는 것을 확인한다

가드를 쓴 뒤 **일부러 어긋나게 만들어** 실패하는지 본다. 확인했으면 커밋 메시지나
CLAUDE.md에 "회귀를 심어 확인함"이라고 적는다. 이 확인을 건너뛴 가드는 통과하는 것 외에
아무 증거가 없다.

## 가드가 못 하는 것 — 대체 경로

| 못 하는 이유 | 대신 무엇을 검사하나 |
|---|---|
| **release에서만 재현**(R8 축소) | 재현이 아니라 **예방**을 검사한다 — keep 규칙의 존재 |
| **네트워크가 필요**(출처 URL 생존) | 가드가 아니라 스킬로. 문서 파일 대조까지는 가드가 한다 |
| **실기기·플랫폼 분기**(`Platform.isAndroid`) | 주입점(provider, `showXxx: bool?`)을 두고 그 값을 검사 |
| **스토어 등록정보** | 로컬 파일이면 가드가 된다(아래 미결 후보) |

## 승격 사례 — 스토어 등록정보 (2026-08-13)

CLAUDE.md가 *"재발하면 가드로 올릴 후보다"* 라고 적어둔 항목을 올린 기록이다.
`versionCode 143`이 **정부 정보 출처 링크 누락**으로 거부됐는데, 지적된 영역은
`자세한 설명 (ko-KR)` 한 곳이었고 **어떤 테스트도 그 파일을 보지 않았다.**

`test/deploy/store_listing_credit_test.dart` 6건이 검사한다 — 면책 주장 셋 ·
데이터셋 URL 넷 + 포털 + 법령 · **두 문서의 URL 집합 일치** · 기관 표 ↔ 실제 호출 양방향 ·
검사 생존.

**가드를 쓰는 동안 드러난 것**: CLAUDE.md는 "iOS 설명에는 면책조항이 없다"고 적고 있었는데
**이미 들어가 있었다.** 부채를 갚고 문서를 안 고친 것이다. 가드는 재발을 막는 것만이
아니라 **문서가 낡았다는 사실을 드러낸다** — 승격 작업의 절반은 대개 문서 정정이다.

URL이 **지금도 200인지**는 여전히 가드가 못 한다(네트워크) — 그건 스킬 쪽 몫이다.

## 절차

1. 어긋난 두 곳을 특정한다. **한 곳뿐이면 가드가 아니라 그냥 테스트다.**
2. 배치: 배포·문서 대조는 `test/deploy/`, 기능은 `test/features/<기능>/`
3. 소스를 **읽어서** 대조한다(문자열을 테스트에 다시 박으면 세 번째 원본이 된다)
4. 위 규칙 넷을 적용한다 — 양방향 · 면제에 이유 · 검사 생존 · 회귀 심어 확인
5. `flutter test <새 가드>` → 통과 확인, 회귀 심어 실패 확인, 원복
6. CLAUDE.md의 해당 함정 항목에 **가드 파일명을 적는다** — 다음 사람이 이미 지켜지는
   것과 아직 아닌 것을 구별할 수 있어야 한다
